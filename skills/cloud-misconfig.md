# 云配置错误

> 云上最常见的不是漏洞，是**配置**：桶公开、元数据可达、密钥硬编码。
> 判断标准是"**能不能读到不属于公开范围的东西**"。

## 一、对象存储桶（最高频）

### 发现桶名
| 来源 | 说明 |
|---|---|
| 页面图片/附件 URL | `xxx.oss-cn-xxx.aliyuncs.com`、`xxx.cos.ap-x.myqcloud.com` |
| JS 里的上传地址 | 常直接写死桶名与目录 |
| 域名 CNAME | `dig` 看是否指向云存储 |

### 三档测试

| 测试 | 判据 | 价值 |
|---|---|---|
| **列目录** | GET `/?prefix=` 或 `?list-type=2` 返回 XML 列表 | ✅ 高（能看到全部文件） |
| **匿名读单个对象** | 直接 GET 已知路径返回文件 | ⚠️ 中（若为公开静态资源则不算） |
| **匿名写** | PUT 一个无害文件成功 | ✅ 高（但**做完立即删除**） |

**判定关键**：桶里是否有**非公开内容**（备份、日志、用户上传、数据库导出）。

### 各云差异
| 云 | 列表接口 | 备注 |
|---|---|---|
| 阿里云 OSS | `?prefix=&max-keys=1` | 返回 XML |
| 腾讯云 COS | `?prefix=&max-keys=1` | 同上 |
| AWS S3 | `?list-type=2` | 同上 |

## 二、云元数据（SSRF 时用）

```
http://169.254.169.254/latest/meta-data/            (AWS)
http://100.100.100.200/latest/meta-data/            (阿里云)
http://metadata.tencentyun.com/latest/meta-data/    (腾讯云)
```

**判据**：通过 SSRF 或命令执行读到元数据内容。

**边界**：
- 只证明**能读到** `/latest/meta-data/` 的目录列表
- **读取 AK/SK 后不实际使用**（那是越界）——只证明"能看到凭据字段存在"

## 三、AK/SK 泄露验证

从 GitHub/JS/日志拿到 AK/SK 后：

```bash
# 阿里云：只做身份确认（只读）
aliyun sts GetCallerIdentity

# AWS：只做身份确认
aws sts get-caller-identity
```

**判据**：返回账号信息即证明有效。

**边界**：
- **只调身份确认接口**，不列举资源、不读数据、不删改
- 报告里密钥打码

## 四、其他云暴露面

| 面 | 测试 | 判据 |
|---|---|---|
| 容器 registry | `/v2/_catalog` | 返回仓库列表 |
| 函数计算/Serverless | 触发器 URL 无鉴权 | 能调用并返回数据 |
| 消息队列（Kafka/RabbitMQ） | 端口暴露 + 匿名连接 | 能列 topic |
| 数据库（RDS） | 公网可达 + 弱口令 | ⚠️ 见 `unauth-exploit` |

## 五、判定标准

| 结果 | 结论 |
|---|---|
| 桶可列出且含非公开文件 | ✅ 高（数据泄露） |
| 桶可匿名写 | ✅ 高（但需立即清理） |
| 元数据可读且含凭据字段 | ✅ 高 |
| AK/SK 有效（身份确认通过） | ✅ 高 |
| 桶只存公开静态资源 | ❌ 不算 |
| registry 可列但全为公开镜像 | ❌ 不算 |

## 六、证据要求

1. 桶：请求 + 返回的 XML 片段（**文件列表只截 3–5 条**）+ 一条对象内容的片段
2. 元数据：请求 + 响应片段（凭据字段打码）
3. AK/SK：身份确认响应（账号 ID 打码）

## 七、边界（红线）

| 禁止 | 原因 |
|---|---|
| 下载桶内全部文件 | 数据泄露风险 |
| 用 AK/SK 列举/读取云资源 | 越界 |
| 匿名写入后不删除 | 遗留垃圾文件 |
| 用元数据凭据横向 | 严重越界 |

## 八、常见坑

| 坑 | 说明 |
|---|---|
| 把公开图片桶当漏洞 | 前端静态资源本就该公开 |
| 忘记看桶 policy | `?policy` 能看到权限配置 |
| 用 `--region` 错了 | 云存储区域必须匹配 |
| 忽略 CDN 缓存 | 桶前面挂 CDN 时看到的是缓存 |
