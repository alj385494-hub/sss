# 按行业选侦察重点

> 不同行业的**公开信息源**和**系统构成**差异很大。
> 用错入口，子域字典再大都扫不到关键资产。

## 一、五类行业对照

### 教育（高校/中小学）

| 项 | 内容 |
|---|---|
| **公开信息源** | 教育部/省厅公示、学校官网"信息公开"、招标公告、教务通知、招生简章 |
| **常见系统** | 教务(jw/jwc)、一卡通(ecard)、图书馆(lib)、研究生(yjs)、科研、OA、邮箱、统一认证(idp/cas)、VPN |
| **命名规律** | 拼音缩写常见：`jw`(教务) `xsc`(学生处) `rsc`(人事) `cwc`(财务) `gzc`(国资) |
| **最易暴露** | 教务系统老版本、招生报名（含身份证）、离校/迎新系统（临时开放）、测试环境 |
| **特别注意** | 学期初/末系统临时开放期；子域极多（一个学院一个站） |

### 医疗

| 项 | 内容 |
|---|---|
| **公开信息源** | 卫健委公示、医院官网"科室介绍"、招标、招聘 |
| **常见系统** | HIS/LIS/PACS、预约挂号、报告查询、体检、随访、互联网医院、OA |
| **命名规律** | `his` `lis` `pacs` `yygh`(预约挂号) `bgcx`(报告查询) `tj`(体检) |
| **最易暴露** | 报告查询接口（IDOR/未授权）、老版挂号系统、厂商统一部署的产品 |
| **特别注意** | **患者数据红线最严**，只取 1–3 条脱敏样本；系统多为厂商产品 |

### 政务/事业单位

| 项 | 内容 |
|---|---|
| **公开信息源** | 政府信息公开目录、招标中标公告、政民互动 |
| **常见系统** | 门户、网上办事、OA、执法、数据开放平台、统一认证 |
| **命名规律** | `zwfw`(政务服务) `open`(数据开放) `bm`(部门) `oa` |
| **最易暴露** | 数据开放平台的 API（常无鉴权）、老版办事系统、附件下载点 |
| **特别注意** | 政务数据敏感性高；注意"数据开放"与"未授权"的边界 |

### 企业（含 SaaS/外包）

| 项 | 内容 |
|---|---|
| **公开信息源** | 官网、招聘 JD、GitHub/Gitee、天眼查/ICP、公众号 |
| **常见系统** | 官网、客户后台、开放平台/API、招聘、商城、管理后台 |
| **命名规律** | `api` `open` `admin` `app` `m` `www` `crm` `erp` |
| **最易暴露** | 开放平台 API 未鉴权、测试环境、GitHub 配置泄露、小程序后端 |
| **特别注意** | 外包/定制公司常一套代码多客户用 → 识别产品 vs 自建 |

### 制造/工业

| 项 | 内容 |
|---|---|
| **公开信息源** | 官网、行业展会、招标、专利 |
| **常见系统** | 官网、经销商/供应商平台、设备管理云、MES/ERP 门户 |
| **命名规律** | `dms`(经销商) `srm`(供应商) `iot` `cloud` `device` |
| **最易暴露** | 经销商平台（业务枚举/越权）、设备管理云（设备 ID 越权） |
| **特别注意** | 不要碰真实设备控制指令（OT 红线） |

## 二、通用侦察次序（任何行业）

```
1. 归属与主体（ICP/页脚/证书）→ 确定 T0 范围
2. 组织画像（recon-org-footprint）→ 知道它用什么系统、谁是供应商
3. 子域（CT + 爆破 + 行业词）→ 数量优先
4. 资产分层（recon-subdomain-deep）→ 选出 P0
5. 前端与 API 面（recon-js-analysis / recon-api-discovery）
6. 对 P0 做深度测试
```

## 三、判定标准

| 结果 | 说明 |
|---|---|
| 找到了该行业特有的系统 | ✅ 入口选对了 |
| 只找到官网+几个静态站 | ⚠️ 入口可能选错（查行业信息源） |

## 四、边界

- 只用公开信息源，不买数据
- 行业特有的敏感面（医疗/政务数据）取证红线更严

## 五、常见坑

| 坑 | 说明 |
|---|---|
| 所有行业都用同一套子域字典 | 会漏掉行业特有系统名 |
| 忽略招标公告 | 里面写着采购了什么系统（含厂商与版本） |
| 忽略学期/业务周期 | 教育开学季、医疗体检季会临时开系统 |
