# 越权与 IDOR

> 判据只有一条：**用 A 的凭据，读到了 B 的数据**。读到"更多自己的数据"不是越权。

## 一、先分类

| 类型 | 定义 | 例子 |
|---|---|---|
| **水平越权** | 同级别用户之间越界 | 改 `uid` 读他人资料/订单 |
| **垂直越权** | 低权限执行高权限操作 | 普通用户调用管理员接口 |
| **上下文越权** | 跨组织/租户 | 改 `tenantId`/`orgId` 读别的单位数据 |
| **未授权** | 完全无凭据 | 见 `api-noauth-hunt`（不是本技能范畴） |

## 二、找越权点（参数清单）

| 参数名 | 含义 |
|---|---|
| `id` / `uid` / `userId` / `memberId` | 用户标识 |
| `orderNo` / `orderId` / `tradeNo` | 订单 |
| `fileId` / `attachId` / `docId` | 文件 |
| `tenantId` / `orgId` / `schoolId` / `deptId` | 租户/组织 |
| `roleId` / `role` / `type` / `isAdmin` | 权限位 |
| `phone` / `idCard` / `stuNo` | 自然人标识 |

**来源**：抓包看请求体/URL/头，前端 JS 里搜参数名，响应里看返回了哪些 id。

## 三、证明方法（重要）

### 方法 A · 单账号参数替换（最常用）

```bash
# 基线：读自己的
curl -s "https://target/api/user?id=<自己的ID>" -H "Authorization: Bearer $TOK"
# 替换：读别人的
curl -s "https://target/api/user?id=<他人ID>" -H "Authorization: Bearer $TOK"
```

**判据**：返回 200 且数据归属变了（姓名/手机/订单号与基线不同）。

**但有个坑**：单账号替换只能证明"能读到另一个 id 的数据"，如果那个 id 恰好不存在或返回空，
无法区分"没权限"还是"数据不存在"。所以需要**对照组**。

### 方法 B · 双账号对照（最强证据）

| 账号 | 用途 |
|---|---|
| A（自己的） | 基线：读自己的数据，记录 id |
| B（另一个合法测试账号） | 用 A 读 **B 的 id**，看是否返回 B 的数据 |

**判据**：用 A 的 token 读到 B 的姓名/手机/订单 → 铁证。

> 拿不到第二个账号时，退而求其次：用**存在性差异**证明——
> `id=有效值` 返回数据、`id=不存在值` 返回空 → 说明服务端没做归属校验（不是"没权限都返回空"）。

### 标识不是自增数时怎么办

| 标识类型 | 获取他人的值 |
|---|---|
| 自增数字 | 直接 ±1 试（**只试 3–5 个**，不遍历） |
| 订单号/流水号 | 看编号规则（日期+序列），构造 1–2 个验证 |
| 哈希/UUID | 从**响应里**找（列表接口、分享链接、导出文件） |
| 复合（`uid:role`） | 拆开分别改 |

## 四、判定标准

| 现象 | 结论 |
|---|---|
| 改 id 返回他人数据（姓名/手机/订单不同） | ✅ 水平越权 |
| 普通账号调管理接口返回 200 + 后台数据 | ✅ 垂直越权 |
| 改 tenantId/orgId 读到别单位数据 | ✅ 上下文越权（价值最高） |
| 返回 200 但是空数组/空对象 | ❌ 可能鉴权正常 |
| 返回 200 但数据与基线完全一致 | ❌ 参数被忽略（服务端用 token 里的身份） |
| 返回 403/401 | ❌ 鉴权正常 |

**特别注意"参数被忽略"**：很多系统明明传了 `uid`，服务端却用 token 里的 uid。
验证方法：把 `uid` 改成明显不存在的值（如 `999999999`），若返回的还是自己的数据 → 参数无效。

## 五、证据要求

1. **基线请求**：读自己的完整报文 + 响应（脱敏）
2. **越权请求**：改 id 后的完整报文 + 响应
3. **数据归属说明**：明确"响应里的手机号/姓名属于另一个人"
4. 若有双账号：附 A、B 两个账号的归属证明（如两个账号的登录态回显不同）

## 六、失败判据

- 改 id 后返回 401/403 → 鉴权正常
- 改 id 后返回空/与自己一致 → 参数无效或无数据
- 需要签名（见 `sign-param-reverse`）且无法复算 → 先解决签名

## 七、边界（红线）

- **只取 1–3 条样本**证明字段，不翻页、不导出
- 敏感字段在报告里脱敏（`138****1930`）
- **不修改他人数据**：只读验证；`PUT/DELETE` 类越权只记录"方法可用"，不实际执行
- 自建账号只能用于验证，不能作为"账号权限"成果
- 不遍历 id（≤5 个测试值）

## 八、常见坑

| 坑 | 说明 |
|---|---|
| 参数被忽略却当成越权 | 改成不存在的值看是否还返自己数据 |
| 只测 GET 不测 POST | 很多越权在 POST/PUT 的 body 里 |
| 忘了改请求头里的标识 | 有些系统用 `X-User-Id` 头 |
| 把"公开数据"当越权 | 商品/公告/科室介绍是公开的 |
| 拿不到第二个账号就放弃 | 用存在性差异也能证明，要写清论证 |
