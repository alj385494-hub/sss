# 补天驳回案例库（Butian Rejection Cases）

> **一句话**：真实审核裁决记录 + 规避规则，用来在**测试阶段**筛掉注定被驳的漏洞，
> 并在**提交阶段**复核报告写法会不会触发驳回。
>
> 与 `butian-submit` 分工：那个写「平台规则怎么说」，本文件写「实际审核怎么判」。

---

## 一、【必读】三问卡（30 秒判断，测试阶段就过一遍）

| # | 问 | 不过怎么办 |
|---|---|---|
| **Q1** | 泄露/拿到的内容**含个人敏感信息**吗？（姓名/身份证/手机/住址/账号/订单/病历） | 不含 → **降级** |
| **Q2** | 能碰到**后台管理功能**吗？（能增删改，不只是能读） | 不能 → **降级** |
| **Q3** | 危害是**已实测的直接后果**，还是要「假设下一步」？ | 靠假设 → **不交** |

**判定**：
- 三问全「否」→ **不提交**（最多并入同站点高价值报告作危害加剧证据）
- Q1 或 Q2 有一个「是」→ 可交，按实测危害定级
- Q3 为「否」→ **一律不交**，无论类型多对口

**加问一条（针对未授权类）**：
- **Q4**：我打开响应体看过里面**真有内容**吗？还是只有空壳/跳登录页？→ 只有空壳 = **误报**（见 R9）

## 二、R 规则表（提交前逐条过，**可增行**）

| 编号 | 规则 | 来源案例 | 违反后果 |
|---|---|---|---|
| **R1** | 纯配置类未授权（只泄露开闭时间、策略、开关、校区、域名、版本号等）**且不含 PII、不含后台功能** → 大概率驳回，**不要提交** | C-001 | 直接驳回 |
| **R2** | **禁止理论影响句式**：`可进一步…`/`理论上可…`/`攻击者可借此…`/`可导致…`/`若结合…`/`可能造成…`。危害只写**已实测的直接后果** | C-001 | 判为「需假设后续步骤」→ 驳回 |
| **R3** | 危害段只写**「实测拿到了什么」**，不写「拿到后能做什么」。句式：`实测未授权获取到：A、B、C（共 N 条/N 字段，其中 X 个有效）` | C-001 | 危害不足 |

> **R3 正面范例（2026-11-13 补，来自补天社区实战文章原文，平台认可的表达）**：
> · 「拿到该平台总共 **573 万用户的昵称、手机号**等信息」← **条数 + 字段**，一句见规模
> · 「前端页面**仅有 5 个字段**，但 API 接口将数据对象的**所有字段均返回**」← **对照组式**，可核对可复现
> · 「未授权获取大量敏感信息，并有接口可修改身份信息造成**任意用户登录**」← 从「读」升级到「写」
>
> 三条共同点：**全是「实测拿到了什么」，零句「可进一步/理论上」**。写危害时照这个句式套。| **R4** | 判定「有无后台管理功能」看页面**是否提供管理操作入口/写操作**；只能读的配置页不算后台功能 | C-001 | 被归为配置泄露 |
| **R5** | 「巧合型危害」不算危害：抢课、绕过缴费、批量注册、爆破登录等**都需要用户主动操作或额外条件**，属理论推演 | C-001 | 驳回 |
| **R6** | 同一套「越权」口径下，**能不能过取决于泄露内容的价值**，不是类型对得上就行。定级前先自问：泄露的东西值钱吗？ | C-001 | 类型对、价值不够 → 驳回 |
| **R7** | **依赖第三方机密才能证明可用性的泄露不算危害**：微信 JS-SDK 签名（验签需 jsapi_ticket←appsecret）、JWT 密钥、短信模板 ID 等。只写「泄露了什么」，不许写「可伪造/可调用」 | C-002 | 判为理论影响 |
| **R8** | **有有效期的凭据要看是否已过期**：jsapi_ticket 7200s、签名 timestamp、一次性 token。已过期或无法在有效期内核验的，按「不可利用」处理 | C-002 | 危害不成立 |
| **R9** | **未授权类必须看响应体内容，不能只看状态码+字节数**。未认证返回 200 不代表泄露——受保护资源常返回「空壳 HTML + JS 跳登录」。必须打开源码确认里面**确有敏感内容**；只有默认模板代码 = **误报** | C-003 | 提交后被判误报，白耗额度 + 影响信誉 |

> 新增规则时：追加一行，编号顺延（R10、R11…），「来源案例」填案例编号，便于回溯。

## 三、打分校准表（别把必驳的漏洞打高分）

| 漏洞形态 | ❌ 曾经怎么打 | ✅ 应该打 |
|---|---|---|
| 纯配置/策略/时间/开关/域名泄露 | 4–5 | **1–2（不建议交）** |
| 未授权读租户/客户标识（无 PII） | 4 | **2–3（有风险）** |
| 未授权读**用户数据**（含 PII） | 5 | **5** |
| 未授权进**后台可操作** | 5 | **5** |
| 需登录态但**无账号验证** | 3 | **1（不可交）** |
| 版本泄露 / phpinfo / 默认页 | 2 | **0（不交）** |
| 依赖第三方机密才能利用的签名/token 泄露 | 4 | **1–2（不可证明）** |
| 未授权但响应体只有默认模板/空壳（Domino / WebLogic / 跳登录页） | 4 | **0（误报，不交）** |

**综合分** = `提交几率(1-5) × 2 + 危害(1-5)`，但**提交几率必须按上表压过**，不许凭感觉打高。

## 四、案例表（**一行一例，可无限追加**）

> 格式固定；**驳回原因原文一字不改**（那是最有价值的资产）。

| 编号 | 日期 | 单位 | 漏洞 | 类型 | 自评 | 裁决 | 关键事实 / 驳回原文 | 根因 |
|---|---|---|---|---|---|---|---|---|
| **C-001** | 2026-11-12 | 某省属师范高校 | 选课系统后台配置页未授权（`xk.*/config`） | 信息泄露 | 中危·13分·几率5/5 | ❌ **驳回（已确认）** | 「未授权页面仅泄露选课开放时间、登录策略、校区等选课规则配置，不含个人敏感信息或后台管理功能，文字所述抢课、绕过缴费等均为需假设后续步骤的理论影响，漏洞细节中展示的情况带来危害较小，漏洞不予收录。」（审核：yuaneuro） | R1+R2+R6 |
| **C-002** | 2026-11-12 | 某SaaS建站平台公司 | `<客户域名>/site/index?id=N` 未授权跨租户配置泄露（PHP var_dump） | 信息泄露 | 中危·11分·几率4/5 | ⏳ **已提交，待裁决** | 泄露字段仅 `share_url`/`reverse_proxy_domain`/`anti_wx_block`/`wechat{debug,beta,jsApiList,openTagList,appId,nonceStr,timestamp,url,signature}`，**无客户名称/联系人/用户数据**；82/120 个 id 有效（样本：涪陵 wap.fuling.com、神木、share.pstcw.net）。加固尝试失败：平台侧 `/site/view`、`/site/detail`、`/site/config`、`/activity/index`、`/user/info` 全 404；微信签名验签需 appsecret 不可得且 timestamp 已过期 6h | R1+R6+R7+R8 |
| **C-003** | 2026-11-12 | 某省属师范高校 | `oa.<客户域名>/domcfg.nsf` Domino 配置库「未授权访问」 | 信息泄露 | 中危·12分·几率4/5 | ❌ **自查为误报（已撤回）** | `/domcfg.nsf` 返回 200/706B，但响应体**只是 Domino 默认空壳**（`_doClick` JS + `<body onload="window.location='/names.nsf?logout'">`），无服务器配置/管理员/IP/数据库列表；`names.nsf`(9782B)、`catalog.nsf`(9784B)、`admin4.nsf`(9783B)、`people.nsf`(9783B)、`mail.nsf`(9781B) **全部返回 OA 登录页** → 目录库均受保护，「可打开通讯录」推论经实测不成立 | R9+R2 |

### 案例详解

#### C-001 江西师大选课系统（首个真实驳回）

| 项 | 内容 |
|---|---|
| 我们写的危害 | 「可提前获悉选课开放时间并卡点抢课」「可绕过缴费限制」→ 命中 R2/R5 |
| 证据链 | 完整（隐私窗口 + 对照组 6560B vs 356B）→ **证据没问题，危害论证才是** |
| 审核认什么 | ①含个人敏感信息？无 ②含后台管理功能？无 ③危害已实测？只有理论 |
| 结论 | 类型完全对口（中危第 5 类「越权访问—绕过认证访问后台」）**仍然驳回** |
| 校准 | 提交几率从 5/5 压到 **1–2** |

#### C-002 某SaaS平台（已提交，加固失败）

| 项 | 内容 |
|---|---|
| 原打算怎么打 | 中危、综合分 11，理由「跨租户读取租户配置，覆盖 82/120 个租户」 |
| 三问卡 | 含 PII？无 → 含后台功能？无 → 危害已实测？有（但只是域名+微信配置） |
| 加固 B（找用户数据） | 平台侧 `/site/*`、`/activity/*`、`/user/*` 相邻接口 **全 404**，无扩展面 |
| 加固 C（签名可用性） | 验签需 jsapi_ticket（appsecret 不可得）；timestamp `1794456922`=04:15:22，已超 7200s → **不可证明** |
| 结论 | 与 C-001 同形态，用户已提交，**结果待回填** |
| 沉淀 | 新增 R7、R8 |

#### C-003 Domino 误报（自查拦截）

| 项 | 内容 |
|---|---|
| 原判断 | 「服务器级配置库 domcfg.nsf 未授权，暴露 OpenDatabase 入口与会话跳转逻辑」 |
| 复核 | 那 706B 的完整内容 = Domino **默认模板代码** + `onload` 立即跳登录页，**没有任何配置数据** |
| 同类库测试 | names / catalog / admin4 / people / mail.nsf **全部 9781–9795B 的 OA 登录页** |
| 结论 | 既无信息泄露也无越权 → **误报，撤回** |
| 沉淀 | 新增 R9 + 校准表一行 |

## 五、本轮复盘（2026-11-11 ~ 11-12）：我们被打脸了四次

### 4 次打脸

| # | 我们以为 | 实际 | 教训 |
|---|---|---|---|
| 1 | 选课系统配置页「几率 5/5、通过 ~70%」 | **驳回** | R1/R2/R6：类型对≠能过，理论影响不算危害 |
| 2 | 化龙巷「4 条可提交」 | **0 条**（全落忽略类） | 收敛的站不要硬凑 |
| 3 | 某SaaS平台「中危 11 分」 | 自查发现无 PII、加固全失败，**可能同样被驳** | R6/R7/R8 |
| 4 | Domino「服务器配置库泄露 12 分」 | **误报**（空壳+跳登录） | R9：不看响应体就下结论 |

### 根因（三条，按影响排序）

1. **把「命中平台口径」当成通过保证** —— 口径只是入场券，危害价值才是决定项
2. **用理论推演凑危害** —— 「可抢课」「可爆破」「可伪造签名」，审核一句话就拆穿
3. **只看状态码和字节数，不读响应体** —— 200 不等于泄露，706B 也可能只是跳转壳

### 行为改变（已写进技能，不是口号）

| 场景 | 现在的做法 |
|---|---|
| 发现候选漏洞 | 先过三问卡 + Q4（响应体里真有内容吗） |
| 写危害段 | 只写「实测获取到 A/B/C（N 条）」，禁写「可…」 |
| 定级打分 | 按第三节校准表压分，不凭感觉 |
| 发现未授权 200 | **必须打开源码看内容**，空壳/跳登录 = 误报 |
| 决定提交 | 先 grep 本文件同型案例 |

## 六、维护协议（**每次拿到新驳回，按这四步做**）

1. **追加案例行**：第四节末尾加一行，`关键事实/驳回原文`**逐字复制**，不改写不概括。
2. **归到 R 规则**：违反哪条？没有对应的就**新增 R(n+1)**。
3. **校准打分表**：自评与实际差很大时，更新第三节对应行。
4. **跑自检**（见第七节），确认表格没坏、编号连续。

> 案例超过 **30 行**时：把最早 15 条移入 `butian-rejection-cases-archive.md`，
> 本节只留最近 15 条 + 一行「更早案例见归档」，避免文件膨胀拖慢加载。

## 七、如何正确读取（给执行侧）

| 时机 | 读哪部分 |
|---|---|
| **阶段 3 发现候选漏洞时** | 第一节三问卡（+Q4）——决定要不要继续投入验证 |
| **阶段 5 写报告前** | 第二节 R 规则 + 第三节打分校准表——决定定级与危害写法 |
| **决定提交前** | 第四节案例表按类型 grep——看有无同型先例 |

```bash
SK=~/.dsh/skills/butian-rejection-cases.md
grep -n "未授权\|信息泄露\|理论影响\|危害较小\|签名\|空壳" "$SK"   # 找同型先例
grep -c '^| \*\*C-' "$SK"                                          # 已收录案例数
grep -c '^| \*\*R[0-9]' "$SK"                                       # 规则数
```

**改完必跑自检**：
```bash
SK=~/.dsh/skills/butian-rejection-cases.md
awk -F'|' '/^\| \*\*C-/{print NF}' "$SK" | sort -u      # 案例列数应统一
awk -F'|' '/^\| \*\*R[0-9]/{print NF}' "$SK" | sort -u   # 规则列数应统一
grep -c '^```' "$SK"                                      # 应为偶数
```

## 八、与其他技能的关系

```
pentest-full-pipeline（怎么测）
        ↓ 产出证据
butian-submit（怎么写报告 / 平台规则原文）
        ↓ 写完报告
butian-rejection-cases（本文件：这条会不会被驳？危害写法踩雷没？）
        ↓ 通过
        才提交
```

**硬要求**：报告写完、点提交前，**必须过一遍三问卡（含 Q4）+ R 规则**。
