# XSS 判定与取舍

> 先说结论：**反射型 XSS 在多数平台是忽略项**（多数平台已明文列出）。
> 值得投入的是**存储型**（影响所有访问者）与**能进后台的 XSS**（管理员 Cookie）。

## 一、判断是哪种

| 类型 | 特征 | 价值 |
|---|---|---|
| **反射型** | payload 从 URL 参数回显到响应 | ⚠️ 低（多数平台忽略） |
| **存储型** | payload 存库，他人访问页面时触发 | ✅ 中高 |
| **DOM 型** | 前端 JS 从 `location` 取值写进 DOM | ⚠️ 低~中 |
| **后台 XSS** | 打进管理后台，触发管理员会话 | ✅ 高（需证明管理员会看到） |

**先分类，再决定要不要花时间。**

## 二、找落点与判上下文

| 回显位置 | 要闭合/绕过的 |
|---|---|
| HTML 文本 | 直接 `<script>` 或 `<img onerror>` |
| 属性内（`value="..."`） | 闭合引号 + 事件属性 |
| `<script>` 块内 | 闭合字符串/语句 |
| JSON 响应被 innerHTML 渲染 | 需看渲染点（DOM XSS） |
| 富文本（编辑器） | 看过滤白名单 |

## 三、判定"能执行"（不要只看回显）

**回显 ≠ 执行**。必须证明脚本跑了：

| 证明方式 | 做法 |
|---|---|
| 弹窗 | 最直观，但截图要含地址栏 |
| **带外回调** | payload 里发请求到你的 OOB，证明执行（最可靠） |
| DOM 变化 | 页面元素被改写（截图对比） |

**禁止**：用 `<script>alert(1)</script>` 反复打**生产站点**——历史上有把站点打出 502 的先例（某CDN服务商事故）。

## 四、存储型 XSS 的证明链

```
1. 在 A 位置提交 payload（留言/昵称/资料/评论）
2. 用另一浏览器（未登录/另一账号）访问展示该内容的页面
3. 证明脚本在你之外的环境执行（OOB 回连 或 弹窗截图）
4. 记录：payload 存哪 → 谁看得到 → 执行后果（能否读 Cookie/发请求）
```

**关键**：必须证明"**他人访问时也会执行**"，只用自己浏览器弹窗证明不了存储型。

## 五、判定标准

| 结果 | 结论 |
|---|---|
| 存储型，他人访问触发，能读会话 | ✅ 高 |
| 存储型，他人访问触发，仅弹窗 | ✅ 中（有实际影响但有限） |
| 后台 XSS，能证明管理员访问会触发 | ✅ 中高 |
| 反射型，仅自己点击链接触发 | ❌ 低（多数平台忽略） |
| 只在 `innerHTML` 里回显但被转义 | ❌ 不算 |

## 六、证据要求

1. 提交 payload 的请求 + 响应
2. **触发环境**：另一账号/无痕窗口访问页面的截图（含地址栏）
3. 执行证据：OOB 回连记录 或 弹窗截图
4. 说明影响面：谁能看到这个页面

## 七、失败判据（什么时候别投入）

- 只有反射型 → **多数平台忽略，不值得做证据**
- 需要受害者主动粘贴 payload 到控制台 → 不算
- 有严格 CSP 且无绕过 → 放弃
- 富文本被白名单过滤且无绕过 → 放弃

## 八、边界（重要）

| 禁止 | 原因 |
|---|---|
| 对生产站反复打 payload | 可能触发 WAF 或把站点打挂 |
| 打管理员后台的会话窃取后使用 | 越界 |
| 用 XSS 做蠕虫/批量影响用户 | 严重越界 |

## 九、常见坑

| 坑 | 说明 |
|---|---|
| 把回显当执行 | 必须证明脚本跑了 |
| 只在自己浏览器验证存储型 | 要证明"他人访问" |
| 忽略 CSP | 有 CSP 时 payload 不执行 |
| 在 SPA 里测反射型 | 前端路由的反射型几乎都是 DOM 型，价值低 |
