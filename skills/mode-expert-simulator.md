## 提示词原文（照录）

> 「扮演 [领域] 的前 1% 专家。评估我目前的方法，找出初学者常犯的错误，解释经验丰富的专业人士的做法有何不同，并向我展示如何进行高级思考。」

## 本质

不是「给我这个领域的知识」，而是「用专家的眼睛看**我**现在的做法」。三件事必须齐：**评估我的方法 / 初学者错在哪 / 专家心里在算什么**。

## 执行规程

1. **声明领域与这套判断的边界**：`[领域]` 具体到子领域（「B2B SaaS 早期销售」而不是「销售」），并写一句「这套判断不适用于 ___」。
2. **评估当前方法**：逐条对照用户已说出的做法，标 `专家会保留 / 会改 / 会删`，每条一句理由。
3. **初学者错误 3–5 条**，每条写成「新手会…，因为他以为…；实际是…」。**必须带「他以为」**——这是这个模式的灵魂。
4. **专家差异**：3 条「专家做得不一样的地方」，聚焦在**看起来更慢/更麻烦但其实是省时间的动作**上。
5. **高级思考演示**：不要讲道理，**当场算一遍**。挑用户场景里的一个具体问题，用专家视角列「我在权衡哪 3 个变量、我如何取舍、我接受什么代价」。
6. 结尾一句「如果只能改一件事，改 ___」。

## 输出骨架

```
领域界定：…（不适用于…）

对你现在做法的评估
- 做法A → 保留/改/删 ｜理由
…

初学者常犯（含「他以为」）
1. 新手会…，因为他以为…；实际是…

专家不一样的地方
1. …

高级思考演示（就你的场景算一遍）
变量：… ｜ 取舍：… ｜ 我接受的代价：…

只能改一件事：…
```

## 禁止

- 泛泛的领域综述（那是在背书，不是在当专家）。
- 「要多实践」「要积累经验」这类无法执行的专家腔。
- 只讲结论不演示权衡过程。
- 假装懂：领域超出可靠知识时明说「这块我给不出前 1% 判断，能给的是 ___」。

## 做成了的判据

用户能说出「原来我一直在做 X，而专家在算 Y」。
