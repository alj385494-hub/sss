# 子域分层与排序

> 子域扫完只是开始。**300 个存活站点里，真正值得打的通常不超过 10 个。**
> 本技能解决"选哪个"，而不是"怎么扫"。

## 一、五类分层（按"离数据多近"）

| 层 | 识别特征 | 优先级 |
|---|---|---|
| **A 业务系统** | 教务/订单/HR/财务/会员/审批/工单；标题含"系统/平台/管理" | ⭐⭐⭐ |
| **B 身份与边界** | 统一认证(idp/sso/cas/auth)、VPN、堡垒机、邮箱 | ⭐⭐⭐（进内网的入口） |
| **C 数据与接口** | api/gateway/open/data/export、swagger、GraphQL | ⭐⭐⭐ |
| **D 边缘与设施** | 防火墙/路由/监控(zabbix/grafana)/CI/registry/数据库端口 | ⭐⭐ |
| **E 展示与废弃** | www/news/lib(静态检索)/blog、默认页、占位页、测试环境 | ⭐ |

**排序原则**：A/B/C/D 都值得花时间，**E 类只看一眼就走**。

## 二、怎么快速分类（自动 + 人工）

```bash
# 从存活清单按关键词粗筛（标题 + 域名）
grep -iE "教务|订单|管理|系统|平台|后台|api|gateway|open|auth|sso|vpn|oa|hr|财务" alive.csv
```

**关键词表**（域名部分）：

| 层 | 域名关键词 |
|---|---|
| A | `jw` `jiaowu` `oa` `hr` `erp` `crm` `admin` `manage` `order` `payment` `ecard` |
| B | `idp` `sso` `cas` `auth` `vpn` `mail` `webvpn` `passport` |
| C | `api` `open` `gateway` `data` `openapi` `graphql` `ws` |
| D | `zabbix` `grafana` `jenkins` `gitlab` `nexus` `harbor` `monitor` |
| E | `www` `news` `lib` `blog` `bbs`（若纯静态）`test` `demo` |

## 三、二次筛选（识别"真系统"）

对 A/B/C 类，逐个确认**是不是真在提供服务**：

| 检查 | 说明 |
|---|---|
| 是否有登录页 | 有登录 = 有业务数据 |
| 是否返回业务数据 | 首页有功能菜单/列表，不是"欢迎使用" |
| 是否是默认页 | 框架默认页（Tomcat/Nginx/IIS/Shibboleth/CAS 欢迎页）= 降级 |
| 是否是 SPA 空壳 | 795B/1KB 左右 + `<div id=app>` = 需要另找接口 |
| 是否有 WAF | 403/202/JS 挑战 = 需要特殊处理 |

## 四、产出：优先级清单

```markdown
## 资产优先级
### P0（先打，3-5 个）
- jw.<域>      教务系统 vX.X  有登录  指纹: 正方
- api.<域>     API 网关       swagger 200
- idp.<域>     统一认证       CAS
### P1
- ecard.<域>   一卡通 SPA
### 观察（E 类，放弃）
- www / news / 15 个静态站群
```

**关键**：明确写"**放弃哪些**"，避免下一轮又重扫。

## 五、判定标准

| 结果 | 说明 |
|---|---|
| 分出了 P0 清单（≤5 个） | ✅ 完成本技能目标 |
| E 类明确标注放弃 | ✅ 同样重要（省预算） |
| 所有子域优先级一样 | ❌ 没做筛选，等于没做 |

## 六、常见坑

| 坑 | 说明 |
|---|---|
| 把 300 个站点全当目标 | 预算摊薄，每个都只扫一遍 → 零命中 |
| 只看标题不看功能 | 标题写"系统"但其实是静态介绍页 |
| 忽略边缘设备 | 监控/CI/registry 常是进内网的路 |
| 忽略"测试环境"子域 | `test.` `dev.` `uat.` 往往无鉴权 |
| 不做放弃标记 | 下一轮重复扫同样的静态站 |

## 七、和扫描的关系

> **先分层，再扫描。**
> 对 P0 的 5 个做深度测试（接口/登录态/上传），远胜于对 300 个做一次 nuclei。
> 300 个站点的 nuclei 扫描通常结果是 0——不是因为没洞，是因为**洞不在通用模板里**。
