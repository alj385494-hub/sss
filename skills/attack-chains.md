# 攻击链组合

> 单点漏洞常被驳回；**串成链的漏洞能证明真实影响**。
> 每条链都要能回答：从哪进 → 经过什么 → 最后拿到什么。

## 链 1 · JS 挖接口 → 未授权 → 响应过度 → PII 取证 ⭐最常用

```
触发：目标是 SPA / 小程序 / 后端 API 独立域名
步骤：
  1. hardcoded-credential-hunt  → 拉全部 JS，搜 api/ 碎片关键词
  2. api-noauth-hunt            → 无凭据/空凭据/换方法 三档探测
  3. 找"下拉/模糊搜索"类接口     → 比对前端展示字段 vs 后端返回字段
  4. 有 PII → 只取 1–3 条样本 + 接口自报 total 证明规模
判定：无凭据返回含姓名/手机/学号的业务数据
停止：全部 401 且无绕过 → 换链 2
```

**为什么强**：从"能找到接口"到"能读到多少人"完整闭环，是最难被驳的形态。

## 链 2 · 403/401 → 绕过 → 后台功能 → 越权

```
触发：已知路径返回 401/403，且前置有网关/WAF/CDN
步骤：
  1. bypass-401-403   → 12 类变体（重点是 --path-as-is + 方法/头部覆盖）
  2. 绕过成功 → 记录该路径能做什么（读/写/管理）
  3. 若是管理功能 → web-idor 测垂直越权（普通账号调管理接口）
判定：状态码 200 且响应体含受保护内容
停止：变体全试完仍 403 且响应一致 → 该路径确实无权限
```

## 链 3 · 硬编码密钥 → 签名复算 → 越权调用

```
触发：前端有 AES/RSA 加密或 sign/code 参数
步骤：
  1. hardcoded-credential-hunt → 定位 key/iv/secret 与用法
  2. sign-param-reverse        → 还原拼接规则，本地复算验证一致
  3. 用自算签名调用需要鉴权的只读接口 → 改 id 看能否读他人数据
判定：自算签名通过 + 读到非本人数据
停止：算法在 WASM 或无 sourcemap 且无行为线索 → 放弃
```

## 链 4 · GitHub 泄露 → 内网地址 → 可达性验证

```
触发：目标有公开组织账号，或 JS 里出现内部服务名
步骤：
  1. github-secret-hunting → 搜 .env/config/jdbc/内部域名（含历史提交）
  2. 提取内网地址与连接串
  3. 对内部地址做只读可达性验证（curl -I），不连数据库
判定：找到真实凭据/内部地址，且地址可达
停止：只有占位符/示例值 → 放弃
注意：数据库连接串**不实测连接**（越界）
```

## 链 5 · 错误信息 → 内网接口 → 未授权

```
触发：目标返回自定义 JSON 错误、堆栈、或日志可访问
步骤：
  1. framework-error-oracle → 识别框架与路由约定（module/controller/method）
  2. error-log-mining       → 若有日志，提取内部接口路径与内网地址
  3. api-noauth-hunt        → 对提取出的内部接口做无凭据探测
判定：内部接口无凭据返回数据
停止：内部接口全部 403/404，或需签名无法复算
```

## 链 6 · 登录态 → 双账号 → IDOR 铁证

```
触发：核心功能在登录后，且已拿到（或可申请）两个合法测试账号
步骤：
  1. session-acquisition → 确认鉴权形态并迁移到 CLI
  2. web-idor            → 用 A 的 token 读 B 的 id
  3. 记录对照组：A 读自己 vs A 读 B
判定：A 的凭据读到 B 的数据
停止：只有单账号时，退化为"存在性差异"论证
```

## 链 7 · 上传 → 解析判定（**高风险，慎用**）

```
触发：存在上传点且上传目录可通过 HTTP 访问
步骤：
  1. web-file-upload → 无害标记文件 + 后缀/MIME 变体
  2. 访问返回路径，看是"原样文本"还是"被解析"
判定：被解析（返回 500/源码/空白）→ 危险信号，立即停止
禁止：上传任何 webshell / 可执行代码
```

## 使用原则

| 原则 | 说明 |
|---|---|
| **一次只走一条链** | 并行跑容易把因果关系搞混，证据也难对 |
| **每步留证据** | 链的价值在于"可复现的因果"，中间步骤缺证据等于断链 |
| **设定停止点** | 每条链写了停止条件，命中就停，别硬挖 |
| **动作可控** | 链要能收得住：取证明样本不批量导出、写操作先备份留回滚、内网扫描控速并排除无关段 |
| **结尾要能一句话说清** | "从 X 进入，绕过 Y，最终拿到 Z（N 条字段）" |

## 常见错误

| 错误 | 后果 |
|---|---|
| 把两个不相关的漏洞说成一条链 | 审核一看就穿，整条作废 |
| 中间步骤没证据 | 无法复现，等于只说结论 |
| 链太长（5 步以上） | 每步都可能有断点，实际跑不通 |
| 为了凑链而夸大后果 | 直接触发"恶意夸大"降级 |

## 实战形态（真实案例，已脱敏）

> 下面是每条链在真实靶标上的**具体长相**。看这些比看抽象步骤更容易对上号。
> 标注「未实战」的链只有抽象形态，遇到时按步骤推进即可。

### 链 1 实战 · 某高校（2026-11）

```
入口：ecard.<主域> 是 795B 的 SPA 外壳（API 驱动）
足迹：
  1. 拉 index.js（456KB）→ 正则提路径 → 挖出 24+ 接口
     /alumuns/*  /apply/*  /auth/bindCard/*  /auth/casConfig ...
  2. 直接请求这些路径 → 全部返回 795B
     ⚠️ 判据生效：长度与首页一致 = SPA 回落页，不是接口
  3. 在 JS 里找 baseURL → 发现遗留的内网调试 URL：
     http://192.168.x.x:8166/server/auth/index?openId=xxx&orgId=2&schoolCode=10051
     → 反推出真实前缀 /server/、租户参数 orgId / schoolCode
  4. 按 /server/ 前缀重试 → 返回 JSON（证明是真接口）
  5. 但统一返回 {"message":"失败"}；POST 后暴露新错误：
     「非法请求v：code值不能为空」→ 签名型鉴权
结论：链走到第 4 步拿到"接口真实存在"，第 5 步卡在签名 → 转链 3
教训：SPA 回落页是这条链最大的假阳性来源，**判长度与首页是否一致**
```

### 链 2 实战 · 通用形态（未实战）

```
入口：<业务域>/admin/ 返回 403，前置是某个 WAF
顺序：
  1. 先记录 403 基线（状态码 + 响应体长度 + WAF 特征串）
  2. curl --path-as-is 逐个试：/admin/  /Admin/  /%61dmin/  /admin/./  /admin;/  /admin%20
  3. 再试方法覆盖：X-HTTP-Method-Override: GET
  4. 差异出现后，用合法登录态访问同一路径做对照（证明拿到了同一份内容）
停止：12 类变体响应逐字节一致 → 确实无权限
```

### 链 3 实战 · 某高校认证中心（2026-11）

```
入口：<认证域> 登录页内联脚本
足迹：
  1. 页面里看到 CryptoJS + slider-verify
  2. 内联脚本命中硬编码密钥：
     key = iv = '85addbxxxxxxx'.substr(0,16)   // AES-128-CBC + ZeroPadding
     用途：加密登录口令
  3. 同一脚本里还有 widget 分发器 /auth/widget?layer=&widget=&action=&type=
     → 试非法 widget/action → 统一"操作失败"，无反射/实例化
结论：**只走到第 2 步**。硬编码密钥单独无实际后果（HTTPS 已保护传输），
     必须配到"用它解出未授权接口返回的加密数据"才成立 → 未达成，判为不提交
教训：这一步的价值是"知道系统怎么加密的"，不是"发现了漏洞"
```

### 链 4 实战 · 某机器人公司（2026-11，未达成）

```
入口：GitHub 组织账号（33 个公开仓库）
足迹：
  1. 组织仓库列表 → 逐仓库看 README / .env.example / config 样例
  2. 搜 "jdbc:" / "accessKeyId" / "secret"
结论：**全部命中示例值/占位符** → 按失败判据放弃
教训：开源公司的 GitHub 往往很干净；**真正的泄露常在离职员工的个人 fork 或 CI 日志里**
```

### 链 5 实战 · 某高校开放平台（2026-11）

```
入口：open.<主域> 根路径 302 → /auth/oauth/login
足迹：
  1. 随机路径返回自定义 JSON：{"message":"module not exist"} → 暴露「模块/控制器/方法」三级路由
  2. /auth/ 不再报 module 错 → 模块存在
  3. /auth/oauth/x → {"message":"method not exists:app\auth\controller\Oauth->x"}
     → 泄露完整命名空间（PHP 风格）+ 控制器存在
  4. 但方法名猜不出来（不能大字典枚举）→ 转从登录页 JS 找真实接口
  5. 登录页找到 /auth/widget?... → 基线可无凭据取验证码，非法参数统一"操作失败"
结论：错误信息给了**路由结构与命名空间**（有价值），但**没通向未授权数据**
教训：错误信息类泄露单独不算成果，它的价值是缩短后续路径
```

### 链 6 实战 · 某机器人公司商城（2026-11，**唯一闭环成功**）

```
入口：用户自注册的普通账号（level=0，无订单、无企业认证）
足迹：
  1. 登录后确认鉴权形态：localStorage['store-token'] = JWT(HS512)
     鉴权头是 Authorization: Bearer <jwt>（不是 Cookie、不是 token 头）
  2. GET /api/order/sales_info → 返回 5 名销售实名 + 性别 + 手机 + 邮箱 + 公司地址
  3. 参数 page/limit/id/uid 全试 → 恒返回 5 条（说明不是"只返自己的"）
  4. 另发现 GET /api/order_config 无 token 与有 token 响应 md5 相同 → 未授权
结论：**完整闭环** —— 普通账号读到他人 PII + 未授权配置
对照：/adminapi/* 用普通 token 全部 403（垂直越权不存在，如实记录）
教训：链 6 的关键不是"改 id"，而是**先确定参数到底有没有被服务端使用**
```
