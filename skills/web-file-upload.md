# 文件上传绕过与利用判定

> 判定分两层：**能不能传上去**（upload），**传上去能不能被解析**（execute）。
> 只有后者才算 getshell 级问题；前者单独往往只是低价值的配置问题。

## 一、先摸清上传链路

| 要确认的 | 怎么确认 |
|---|---|
| 上传接口 | 抓包看 `/upload`、`/api/file`、`/common/upload` |
| 是否有登录态 | 无凭据能否直接上传（=未授权上传，价值更高） |
| 校验在哪层 | 前端（可绕过）、后端（看响应）、WAF（看拦截页） |
| 落到哪 | 响应里返回的 URL/路径（是否可直接访问） |
| 谁在解析 | 上传目录是否在 Web 根、后缀是否被应用解析 |

## 二、常见校验与绕过

| 校验类型 | 绕过思路 | 注意 |
|---|---|---|
| **前端 accept/onchange** | 直接发包，绕过 JS 校验 | 最容易 |
| **Content-Type** | 改 `image/jpeg` 等合法 MIME | 后端只查头 |
| **后缀黑名单** | `.php5`/`.phtml`/`.pHp`/`.php.`/`.php `（尾空格） | 看中间件解析规则 |
| **后缀白名单** | 双后缀 `.jpg.php`、`.php.jpg`、`.php%00.jpg` | 看是否取最后一段 |
| **内容检测（getimagesize）** | 图片头 + 后附代码（GIF89a + PHP） | 需二次解析漏洞配合 |
| **文件名重命名** | 若保留原名，注意 `../` 与特殊字符 | 路径穿越另算 |
| **解析漏洞** | Apache 多后缀、Nginx `%00`/`.php.jpg`、IIS `;.jpg` | 依赖中间件版本 |

## 三、执行步骤（**全部用无害文件**）

### 步骤 1 · 基线上传
上传一个正常图片，记录：
- 请求（是否带 token）
- 响应（返回的 URL 长什么样）
- 该 URL 能否直接访问

### 步骤 2 · 逐项试探（每次改一个维度）

```bash
# a) 改 Content-Type
curl -s -X POST "https://target/upload" -H "Authorization: Bearer $TOK" \
  -F "file=@proof.txt;type=image/jpeg"

# b) 改后缀（无害内容）
cp proof.txt proof.php5
curl -s -X POST "https://target/upload" -H "Authorization: Bearer $TOK" \
  -F "file=@proof.php5;type=image/jpeg"
```

**`proof.php5` 的内容只放一行标记**，例如：
```
UPLOAD_TEST_MARKER_2026
```
**绝对不要放可执行代码/webshell**。

### 步骤 3 · 判断是否被解析
访问返回的 URL：
- 返回 **原样文本**（含标记）→ 只是**静态存储**，没解析
- 返回 **500/源码/空白** → 说明后端尝试解析了（**危险信号，立刻停止**）
- 返回 403/404 → 上传目录不对外，价值下降

## 四、判定标准

| 结果 | 定级 |
|---|---|
| 上传后可被解析执行（含命令回显） | ✅ 严重（需有明确回显才算，不做假设） |
| 未授权即可上传任意文件（无需登录） | ✅ 中高（配合解析即严重） |
| 上传后路径穿越写入 Web 根 | ✅ 高 |
| 能传任意后缀但只做静态存储 | ⚠️ 低（配置问题） |
| 只绕过前端校验（后端仍拦） | ❌ 不算 |

**关键**：报告里必须写清"**传到哪 + 谁能访问 + 是否被解析**"三件事，只写"可上传"会被判危害不足。

## 五、证据要求

1. 上传请求（含文件内容标记）+ 服务端响应（返回的路径）
2. 访问该路径的响应（证明落地位置与解析行为）
3. 若被解析：解析后的**无害回显**（如 `echo` 出标记），不放命令执行结果
4. 说明上传目录是否在 Web 根

## 六、失败判据

- 所有变体都返回"文件类型不允许" → 校验在后端且严格，转其他点
- 上传成功但返回的 URL 需要鉴权访问 → 价值下降，记录即可
- 上传目录不可通过 HTTP 访问 → 除非能证明可解析，否则放弃

## 七、边界（**最重要的一节**）

| 禁止 | 原因 |
|---|---|
| 上传 webshell / 一句话木马 / 冰蝎马 | 可传——但先传无害证明文件验证解析，落地即登记 `cleanup`，交付前必须删除；不留在生产 |
| 上传可执行脚本并触发执行 | 会改变目标状态，且可能触发告警 |
| 上传后不清理 | 必须删除测试文件（若接口支持删除），或明确记录位置 |
| 上传大文件测试 DoS | 禁止 |

**只允许**：上传内容为无害标记文本的小文件，验证后缀/MIME/路径行为。

## 八、常见坑

| 坑 | 说明 |
|---|---|
| 只看"上传成功"就结论 | 没有解析就是低价值 |
| 忽略未授权上传 | 无 token 能传，比登录后能传价值高得多 |
| 上传目录带签名/时效 | 返回的 URL 可能是临时签名链接，不代表公开可访问 |
| 忘记记录返回路径 | 后面无法证明落地位置 |
