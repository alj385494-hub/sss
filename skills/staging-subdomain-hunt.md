# 测试环境发现

> 测试环境三件套：**调试开着、鉴权松、数据是真的**。
> 但正因为数据可能真实，**取证红线与生产一致**。

## 一、命名字典（按命中率）

| 类别 | 前缀 |
|---|---|
| **环境** | `test` `testing` `dev` `develop` `uat` `sit` `pre` `preprod` `staging` `stage` `beta` `demo` `sandbox` |
| **版本** | `v1` `v2` `new` `old` `bak` `backup` `temp` `tmp` |
| **内部** | `internal` `intranet` `local` `office` `admin` `manage` `console` `portal` |
| **系统后缀** | `-test` `-dev` `-uat` `-pre`（如 `jw-test`、`oa-dev`） |
| **端口** | `8080` `8081` `8443` `9000` `9090` `3000` `5000` `7001` |

## 二、执行

### 步骤 1 · 子域爆破（DNS 层）
```bash
# 用环境词 + 已知业务名组合
for p in test dev uat pre staging beta demo; do
  for b in jw oa api portal ecard; do
    echo "$p-$b" ; echo "$p.$b" ; echo "$b-$p" ; echo "$b.$p"
  done
done > staging.txt
# 解析（带轮询，别并发过高）
dnsx -l staging.txt -a -resp -o staging_resolved.txt
```

### 步骤 2 · 端口探测（同 IP 的非标端口）
```bash
naabu -host <主站IP> -p 3000,5000,7001,8000,8080,8081,8443,9000,9090 -silent
```
**注意**：非标端口 200 的，按"独立站点"测（Host 头可能不同）。

### 步骤 3 · 判断"是不是测试环境"

| 特征 | 说明 |
|---|---|
| 页面有 `DEBUG=true` / 详细报错栈 | 调试开着 |
| 无登录页或登录可跳过 | 鉴权松 |
| 页脚年份旧 / "测试版"字样 | 老版本 |
| 与生产内容相似但版本低 | 同源不同版本 |
| `/actuator`、`/debug`、`/swagger` 可访问 | 调试端点开放 |

## 三、"同库"的判定（**重要**）

**不要**为了判断是否同库去改数据。用**只读**方式：

| 方法 | 做法 |
|---|---|
| 对比同一内容的 ID | 生产某条公开信息 ID 与测试环境是否一致 |
| 对比文章/公告 | 测试环境有生产上的同一篇公告 → 高度疑似同库 |
| 对比用户 ID 空间 | 登录页提示的用户名规则是否一致 |

**红线**：
- 发现疑似真实用户数据 → **只取 1–3 条脱敏样本**，不导出
- **不修改**测试环境任何数据（有些测试环境直连生产库，一改就是生产事故）

## 四、判定标准

| 结果 | 结论 |
|---|---|
| 测试环境可匿名访问业务功能 | ✅ 中高（未授权） |
| 测试环境调试端点开放（actuator/堆栈） | ✅ 中 |
| 测试环境与生产同库且含 PII | ✅ 高（但取证严格受限） |
| 只是空白占位页 | ❌ 无价值 |

## 五、证据要求

1. 子域/端口发现记录
2. 访问证据（页面截图/响应片段）
3. 若涉及数据：1–3 条脱敏样本 + 说明"未修改"

## 六、失败判据

- 环境词全部 NXDOMAIN → 放弃 DNS 层
- 非标端口全部拒绝 → 放弃端口层
- 找到的测试环境需登录且无注册 → 记录后放弃

## 七、边界（红线）

| 禁止 | 原因 |
|---|---|
| 在测试环境做写操作 | 可能直连生产库 |
| 下载测试库数据 | 数据同样受保护 |
| 把测试环境当"沙箱随便玩" | 常见误解，风险最大 |

## 八、常见坑

| 坑 | 说明 |
|---|---|
| 只爆破前缀不爆破后缀 | `jw-test` 和 `test-jw` 都要试 |
| 忽略非标端口 | 测试环境常在 8080/8081 |
| 认为测试环境无真实数据 | 反向：**测试环境数据往往就是生产拷来的** |
| 在测试环境试破坏性 payload | 可能同步到生产 |

## 实战教训（2026-11，某高校）

### 1. DNS 层全灭是常态，**端口层才是主战场**

本轮 300 条环境词组（21 环境词 × 12 业务名 + 后缀形式 + 补测）**全部 NXDOMAIN**，
但同 IP 的非标端口扫出了**一个未登记的真实系统**（`:3000` 蒙医药数据资源库，Next.js）。

> **规则**：DNS 层 0 命中**不要收工**，接着做端口层（18 个非标端口 × 已知 IP），
> 从端口层挖到"未登记的生产/项目系统"与挖到"测试环境"等价，甚至更有价值。

### 2. "找到未登记系统"也算这个技能的成功

本例最终没有测试环境，但找到了：
- `:3000` Next.js 系统（有 `/admin` 与 **`/register` 自助注册**）
- `:9090` nginx 默认页（无价值，明确放弃）

**结论写法**：写"未找到测试环境，但发现 1 个未登记系统 + 1 个无价值端口"，
而不是笼统的"未发现"。

### 3. `/register` 可用会推翻"无注册入口"的结论

阶段 2.5 若已声明"目标所有系统均无注册入口"，后续一旦发现可自助注册的入口，
**必须回到 state 修正这条结论**（它直接影响"能测多少面"的判断）。

### 4. 系统名要同时试 DNS 与 Host 头

本轮 `jwxt/ehall/cas/sso/auth/ykt/pay/card` 只做了 DNS（全 NXDOMAIN），
**没当 Host 头打**（受 vhost ≤200 配额限制）→ 这是遗留项，重测时优先。
