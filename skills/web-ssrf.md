# SSRF 探测与判定

> 唯一硬判据：**请求确实由目标服务器发起**。本地能访问不算，你必须看到目标侧的痕迹。

## 一、找 SSRF 点（参数清单）

| 参数/功能 | 典型字段 |
|---|---|
| 图片/头像 URL | `url`、`imgUrl`、`avatar`、`picUrl`、`src` |
| 文件导入/远程下载 | `fileUrl`、`remoteUrl`、`downloadUrl` |
| 回调/通知 | `callback`、`notifyUrl`、`webhook`、`redirect_uri` |
| 代理/抓取 | `target`、`host`、`link`、`fetch` |
| 文档预览/转换 | `docUrl`、`pdfUrl`、`previewUrl` |

## 二、三种验证方式（按可靠性）

### 方式 1 · OOB 带外（最可靠）

```bash
# 用 DNS 回调（需自备 DNSLog 或 collaborator 类服务）
curl -s "https://target/api/fetch?url=http://<你的唯一子域>.oob.example.com/"
```
**判据**：OOB 平台收到 DNS/HTTP 请求，且时间戳与你的请求对应 → 确证 SSRF。

### 方式 2 · 内网指纹差异（无 OOB 时）

| 探测 | 观察 |
|---|---|
| `http://127.0.0.1:22` | 连接被拒 vs 超时 vs 返回 banner |
| `http://127.0.0.1:6379` | 返回 `-ERR unknown command` 之类 |
| `http://169.254.169.254/latest/meta-data/` | 云元数据（云主机上才有） |
| `http://10.0.0.1:80` | 超时时间差异 |

**判据**：不同内网地址返回**不同的错误/耗时/内容** → 说明真的发出了请求。

### 方式 3 · 回显型（最理想）

响应里直接带回目标 URL 的内容 → 直接确证，并能读内网页面。

## 三、执行步骤

1. **基线**：先填一个正常公网 URL，确认功能正常、记录响应格式
2. **换内网**：填 `http://127.0.0.1:80`，看响应变化（内容/错误/耗时）
3. **OOB**：填唯一子域，查 OOB 平台是否有回连
4. **协议扩展**（谨慎）：`file://`、`gopher://`、`dict://`
5. **绕过**（若被拦）：十进制 IP（`2130706433`）、`[::1]`、`127.0.0.1.nip.io`、短链接、`@` 混淆

## 四、判定标准

| 现象 | 结论 |
|---|---|
| OOB 收到回连 | ✅ 确证 SSRF |
| 回显内网页面内容 | ✅ 确证（且危害最高） |
| 不同内网端口返回不同错误/耗时 | ✅ 高度可能（需 OOB 补证） |
| 只返回"获取失败"、无差异 | ❌ 无法证明 |
| 返回 200 但内容是自己站的页面 | ❌ 不是 SSRF |

## 五、证据要求

1. 请求报文（含注入的 URL）
2. **OOB 记录截图/日志**（时间戳要对得上）
3. 内网探测的响应差异对比（同一参数，不同目标地址）
4. 若读到内网内容：截取**一小段**证明，不批量抓

## 六、失败判据

- 所有内网地址响应一致（都是同一个错误）→ 可能是前端直接拒绝，没发请求
- OOB 无回连且无响应差异 → 放弃
- 参数被白名单限制且无法绕过 → 记录后放弃

## 七、边界（红线）

| 禁止 | 原因 |
|---|---|
| 用 SSRF 扫内网端口段 | 会被判定为"对内网扫描"，多数平台明令禁止 |
| 经 SSRF 读取云元数据凭据后使用 | 越界；只证明"能读到" |
| 用 SSRF 攻击内网第三方服务 | 属对第三方攻击 |
| gopher 打 Redis 写马 | 越界 |

**允许**：证明"目标能访问某内网地址" + 最多 3 个内网目标做差异验证。

## 八、常见坑

| 坑 | 说明 |
|---|---|
| 本地能打开就当 SSRF | 必须在目标侧留痕 |
| 忽略 DNS 缓存 | OOB 子域要唯一（带随机串） |
| 只看 HTTP 状态码 | SSRF 常是盲的，靠 OOB 或耗时判断 |
| 一次探测几十个内网 IP | 属扫描，注意噪声与命中率 |
| 忘记看响应耗时 | 超时差异本身是很强的证据 |
