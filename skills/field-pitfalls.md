# 踩坑速查：成片假象先怀疑工具，再怀疑目标

> 全部来自 2026-11 六靶标实战胜负。**方向**：一个目标"看起来死了"，先证明是**我这边的坑**，
> 再写"目标不可达"。写错结论的代价是报告被驳，白跑半天。

## 一、工具本地坑（一定先排除这三条）

| # | 坑 | 症状 | 正确做法 |
|---|---|---|---|
| 1 | **Burp Repeater 的 Target 是独立字段** | 改了 `Host:` 头，实际仍连上一个请求的主机 → 返回 `HTTP Host Error` 或别人的页面 | 点右上 Target 文本，在弹窗里**分别填 Host 与 Port**，需要时勾 `Use HTTPS`；改完先看响应里的 `Server`/`X-Powered-By` 是否换家 |
| 2 | **`curl -o` 在连接失败（exit 000）时不覆盖旧文件** | 上一轮的结果被当成本轮，误判"页面回来了" | 采样前 `rm -f out.txt`；或用 `-w '%{http_code}'` + 校验文件时间；批量脚本里一律先删 |
| 3 | **HTTPS vhost 用 `-H "Host:"` 会毁掉 SNI** | 全部 000，误判"站点不存在" | 用 `--resolve "<域名>:443:<IP>"`（保留 SNI）或 `curl -k --resolve`；HTTP 才用 `-H "Host:"` |
| 4 | **`nmap -p- --min-rate 600` 会打爆家用 NAT** | 目标全 filtered、全死 → 制造"目标下线"假象 | 降速（`--min-rate 150`、`-T3`）；**同批必须带正对照**（一个已知可达的站 + 一个公网大站），对照不通就是本地出口问题 |

## 二、出入口与 DNS

| # | 坑 | 正确做法 |
|---|---|---|
| 5 | **IPv6 优先会把工具拖死** | `curl -4`，或 `--resolve` 直指 IPv4；Kali 内同理（它默认先给 AAAA） |
| 6 | 把 `240e:45::8888` 当成"被投毒的解析结果" | 那是**系统 DNS 服务器地址**，不是记录。旧结论已证伪，别再去修 DNS |
| 7 | 宿主解析正常但工具超时 | 先 `curl -4 -sS -o /dev/null -w '%{http_code} %{time_total}'` 单独验一次，再动工具 |

## 三、WAF 与封禁（判"被封"而不是"站挂了"）

| # | 事实 | 用法 |
|---|---|---|
| 8 | **WAF 常只追加响应头，不改写 body** | 奇安信云 WAF（`WZWS-RAY`）实测只加头 → 看头就能判"经过了 WAF"，不要以为 body 干净就是直连 |
| 9 | **首访 cookie 门**：`www` 不带 `visited=1` 返回 200 假象 | 第二次带 cookie 复测；两次响应体逐字节比对 |
| 10 | **安全狗触发封禁 ≈ 8 分 18 秒**（两句 `;waitfor delay` 之后） | 封禁期全站返回 **200 / 2375B「您所在 IP 已被设置成禁止访问」**——**200 不等于正常**，看长度与固定文案 |
| 11 | 被封 ≠ 目标下线 | 换一台无关的资产复测：它也异常 → 是本出口被封；它正常 → 是单站封禁。记录"封禁特征 + 恢复时间"再决定等或换出口 |

## 四、把"不存在"判错（最常见的报告翻车点）

| # | 假象 | 正确做法 |
|---|---|---|
| 12 | **软 404**：任何路径都 200，长度接近 | 用**应用自己的错误分流**做 oracle：`/error/pagenotfound`、404 JSON、`403 Status:4010` 等四口径比对；再拿随机路径的响应做基线 |
| 13 | **`.ashx` / `.do` / handler 不带参数一律 soft-404 同体** | handler 枚举**必须带参复测**；同体说明"路由到了处理器"而不是"不存在" |
| 14 | **统一 403 不代表文件存在** | 用不受过滤的扩展名变体复测（`web.config` → `web.config.txt`）；能读 = 过滤层黑名单，不能读才可能是真没有 |
| 15 | **客户端 TLS 报错当成目标特征** | `packet length too long` 是 OpenSSL 把明文 HTTP 当 TLS record 解析的**本地报错**，恰好是该端口跑明文 HTTP 的强指纹——判"无 banner + TLS 拒绝 = 二进制服务"之前，**先发一次 `GET /`** |
| 16 | **同产品两个实例暴露面可能完全不同** | 上海科大 `vpn` 是完整 aTrust 门户，`sslvpn` 只跑静态层（同路径全 404 且无 `X-Server`）→ "一条 Nday 打两处"被证伪。**逐实例复测，不要一条结论推全站** |
| 17 | 厂商自研产品的响应头是最好的路由 oracle | `X-Server: aTrust` 这类非标头能把「路由不存在」与「处理器存在但拒绝」分开——先看头再猜路径 |

## 五、写结论前的三条自检

1. **成片异常 → 先换方法验一次**（换 IP / 换 UA / 加正对照 / 换协议），排除本地坑再写"目标不可达"。
2. **"不存在"要有对照**：随机路径基线 + 同应用已知存在的路径，两者对比才能说"这个路径没有"。
3. **封禁/超时这类结论必须带时间与恢复证据**，否则下一轮会重复踩。

> 与 `framework-error-oracle`（用报错做枚举）、`vhost-enumeration`（Host 与 SNI 手法）、
> `bypass-401-403`（403 的十几种绕过）、`opsec-hygiene`（封禁与收口）配套使用。

## 六、"响应相同"有两种相反的含义（2026-11-15 实战翻车点）

**同体 ≠ 放行**。看到"改参数后响应逐字节相同"，先别急着下"它不校验参数"的结论——
必须回答：**它是"校验了但不影响结果"，还是"根本没读这个参数"？**

| 现象 | 错误结论 | 正确判据 |
|---|---|---|
| 改签名 / 改 claim / 传垃圾串 / 不传参数，响应**完全相同** | 「它不校验签名 → 可任意构造」 | **先看它到底读没读这个参数**：若"不传参数"与"传合法值"响应也相同，说明**参数根本没被读**，不是"没校验" |
| 同上 | 「它能被任意令牌通过」 | 真正放行的证据是：**响应里出现业务数据 / 跳转 / 会话 / 可执行操作**；`data:null` + 无 `Location` + 无 `Set-Cookie` = **没放行** |

**反例（A1，2026-11-15，河北医大 `openurlCheck`）**：
对「正常签发令牌」「签名段改 32 个 0」「纯垃圾 `AAAAAAAA`」「空值」「完全不传参数」五种输入，
响应**逐字节相同**（72B，`{"code":1000,"data":null,"message":"不是巡检用户"}`）。
上一版报告写成"该端点接受任意构造令牌"——**读反了**。
正确结论：它连 `jwt` 参数都不读，真正的门是"匿名会话不是巡检用户"，且 `data` 恒为 `null`，**一点没放行**。

**配套检查**
1. **加一个"不传参数"的对照组**——如果它和"传合法值"一样，参数就没被读取；
2. **看响应里有没有"东西"**：业务字段、`Location`、`Set-Cookie`、文件字节——有才算放行；
3. **区分三种拒绝**：格式错（`jwt format error`）/ 验签失败（`jwt verify error`）/ 权限不足（`不是巡检用户`）——
   只有第一种能靠"改格式"绕过，第三种是权限问题，跟令牌无关；
4. **补参对照**：怀疑"拒绝是因为缺必填参数"时，补齐 1 次再试，能排除一整类误判。

## 七、"被拦截"不等于"不存在漏洞"（2026-11-15 重扫教训）

**边界设备挡住了请求，恰恰说明它认出了这个 payload** —— 目标很可能真有这个洞，只是被 WAF 截在前面。

| 现象 | 错误结论 | 正确判据 |
|---|---|---|
| 攻击 payload 返回 `RST(000)` / `510` / `403 封禁页`，而普通请求 200 | 「目标没这个漏洞」 | **先定位阻断发生在哪一侧**（见下），再决定结论 |
| 同上，但换出口后**仍 RST** | 「卡在 WAF，换源能过」 | 目标侧拦。换出口意义有限 |
| 同上，但换出口后**返回 200** | 「过了 WAF = 漏洞存在」 | ❌ **这是最危险的错误结论**。链路侧阻断被绕过而已，必须再判"后端读没读这个参数"：把特征值换成无害值，若响应**与无害对照逐字节相同** → **参数未被读取，漏洞不存在** |
| 整站所有路径都 5xx | 「站点挂了」 | 看**是否固定耗时**（如恒 21.5s）= 上游链路断；看**随机路径是否 404**（能 404 说明应用活着）= 只有特定前缀被拦 |
| RST 之后所有请求都失败 | 「IP 被封了」 | **隔几个请求再打一个正常页面验证**。本案 RST 第 44 次后 `GET /login.jsp` 仍 200/56236B → **是 payload 特征触发，不是封 IP**，出口可用 |

**本案实例（某民族院校 Landray EKP，44 请求）**
- `POST custom.jsp` body `a=1` → `200/2B`；`var=abc` → `200/2B`；`var={"x":"abc"}` → `200/2B`
- 一旦出现 `file`（无论 `file=abc`、`file=/etc/passwd`、`{"file":"..."}`、`file`、multipart、PUT、HTTP 80、换 vhost）→ **全部 `000 RST`**
- 结论：**`custom.jsp` 存在、接受 `var` JSON、后端有 `file` 处理分支** —— WAF 只在边界拦这个关键词。
  「读不到配置」是**出口问题**，不是「漏洞不存在」。换出口有实质成功可能。

**另一条容易误判的**：`/data/./sys-common/datajson.js` 绕过了 WAF（500 而非 RST），但后端路由不认 `./`
→ **绕过 WAF ≠ 打通后端**，两层要分开验。

**处置建议**
1. 遇到特征词拦截，**先做无害值对照**锁定触发词，把结论写成"规则边界"而不是"漏洞不存在"；
2. 判定「换出口是否值得」：规则命中（可换源绕过）vs IP 封禁（换了也可能连带封）；
3. 报告里若写"未发现"，必须注明**是否被拦截**，否则下一轮会重复同样的失败。

### 七之二、三步定位：阻断在哪、参数读没读、漏洞在不在（2026-11-15 换出口实战后修订）

**第一步：定位阻断位置**（判"要不要换出口"）
同一 payload 分别在**直连 / 代理出口 / 移动网络**各发 1 次：
- 只有直连 RST、代理 200 → **链路侧阻断**（运营商、公司网关、免费代理自身），不是目标 WAF
- 所有出口都 RST → 目标侧拦截
- 所有出口都 TCP 不通 / ICMP 100% 丢包 → **路由不可达**（如腾讯云 ↔ CERNET），不是任何一方的策略

**第二步：判后端读没读这个参数**（判"漏洞在不在"）
拿到干净响应（200）之后，做**无害值对照**：
```
POST /x.jsp  a=1                      → 200 / 2B / md5=AAA     ← 基线
POST /x.jsp  var=abc                  → 200 / 2B / md5=AAA     ← 参数名无关
POST /x.jsp  file=abc                 → 200 / 2B / md5=AAA     ← 值无害
POST /x.jsp  file=/WEB-INF/web.xml    → 200 / 2B / md5=AAA     ← ★ 攻击值也同体
```
四个 md5 全等 → **后端根本不读 `file`** → 漏洞不存在（不是"读不到"，是"没有这个功能"）。

**第三步：只有前两步都过了，才谈"换出口/绕过"**

**实战反例（2026-11-15，某民族院校 Landray EKP）**
- 本地直连 `file=` 载荷 → `000 RST`；换代理 `<PROXY_IP>:8888` → `200 / 2 字节`
- 当时据此推断"WAF 只拦关键词、后端有该分支、换源能过"——**推断错了**
- 换出口后做无害值对照：`a=1`、`var=abc`、`file=abc`、`file=/WEB-INF/web.xml` **四个响应 md5 全等（`81051bcc`，2 字节 CRLF）**
- 真相：RST 来自**出口链路的关键词阻断**，目标后端**压根不消费 `file` 参数**；换出口只是拿到了出口的干净通道，什么都没读到
- 同时排除：`datajson.js` → 401 JSON（需鉴权）、附件接口 → 302（需登录）→ 该 EKP 鉴权正常

**记住这句话**：**能过 WAF 不等于有漏洞；能 200 不等于读了参数。**
