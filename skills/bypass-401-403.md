# 401/403 绕过

> 核心思想：**鉴权发生在哪一层，就绕过哪一层**。
> 反向代理按一种路径格式做判断，后端按另一种格式路由 → 攻击面就在这个差异里。

## 一、什么时候用

- 目标路径返回 `401 Unauthorized` / `403 Forbidden`
- 前面有 WAF / API 网关 / CDN，且拦截页样式统一
- 同一资源的不同写法返回不同状态（说明存在规范化差异）
- 已知框架：IIS、Tomcat、Spring、Nginx、Apache、WebDAV

## 二、前置（**最重要的两条**）

1. **必须保留原始路径**：`curl --path-as-is`，否则 curl 会自动规范化 `../`、`//`，你的绕过根本没发出去
2. **先建立被拒基线**：记录状态码、响应头、响应体长度，后面每个变体都与它对比

## 三、路径类绕过（10 种）

对同一个受保护路径 `/admin/panel` 依次试：

| # | 变体 | 例子 | 生效条件 |
|---|---|---|---|
| 1 | 尾斜杠 / 缺斜杠 | `/admin/panel/` | 代理规则精确匹配、后端宽容匹配 |
| 2 | 大小写 | `/Admin/Panel`、`/ADMIN/panel` | 代理区分大小写、后端不区分（IIS/Windows） |
| 3 | 单次 URL 编码 | `/%61dmin/panel` | 代理解码前匹配、后端解码后路由 |
| 4 | 双重编码 | `/%2561dmin/panel` | 代理只解一次 |
| 5 | Unicode/超长编码 | `/%u0061dmin`、`/admin%2fpanel` | 特定中间件 |
| 6 | 点段穿越 | `/admin/../admin/panel`、`/./admin/panel` | 代理不折叠点段 |
| 7 | 空字节 | `/admin/panel%00.jpg` | 老版本 Java/PHP |
| 8 | 路径参数 | `/admin/panel;.css`、`/admin/panel;a=b` | 代理把 `;` 后当参数、后端忽略 |
| 9 | 尾部特殊字符 | `/admin/panel.`、`/admin/panel~`、`/admin/panel%20` | 代理精确匹配失败、后端容错 |
| 10 | 反斜杠 | `/admin\panel`、`/admin/..\panel` | IIS / Windows 后端 |

## 四、方法与头部类绕过（补充）

| 手法 | 做法 | 说明 |
|---|---|---|
| 方法覆盖 | `X-HTTP-Method-Override: PUT`、`X-Method-Override` | 网关只看 POST |
| 换方法 | 同一路径 GET/POST/PUT/DELETE/OPTIONS/PATCH 全试 | 鉴权只挂个别方法 |
| 头部覆盖 | `X-Original-URL: /admin`、`X-Rewrite-URL: /admin` | 部分网关信这个头 |
| 客户端 IP 伪造 | `X-Forwarded-For: 127.0.0.1`、`X-Real-IP`、`X-Client-IP` | 白名单按 IP 判断 |
| Host 覆盖 | `Host: localhost`、`Host: 127.0.0.1` | 内部 vhost 放行 |
| Content-Type 变换 | JSON ↔ 表单 ↔ multipart | 不同解析器不同鉴权链 |

## 五、判定标准

| 结果 | 含义 |
|---|---|
| 状态码从 401/403 变 **200**，且响应体含**受保护内容标记** | ✅ 绕过成功 |
| 200 但响应体是默认页/错误页 | ❌ 只是没被拦，不算绕过 |
| 状态码变化但内容为空 | ❌ 需要进一步看响应头/长度差异 |
| 返回 302 跳到登录页 | ❌ 鉴权仍在生效 |

**必须做对照**：把绕过成功的响应与"合法登录后"的响应比对，确认拿到的是同一份内容。

## 六、证据要求

1. 被拒基线：原始请求 + 401/403 响应（含状态行与关键头）
2. 成功变体：同路径的变体请求 + 200 响应片段
3. 对比说明：为什么这个变体绕过了（哪一层没规范化）

## 七、失败判据

- 12 类变体全试完仍是 403，且响应体逐字节一致 → **该路径确实无权限**，放弃
- 所有变体都返回同一个 WAF 拦截页（特征串一致）→ 是 WAF 在拦，转 WAF 识别而不是继续绕
- 绕过只对静态资源生效、对接口无效 → 记录但不作为漏洞

## 八、常见坑

| 坑 | 说明 |
|---|---|
| 没用 `--path-as-is` | curl 自己把 `../` 规范化了，你以为发了其实没发 |
| 只看状态码 | 有些系统 200 但内容是错误页 |
| 忽略 CDN 缓存 | 变体请求命中了 CDN 缓存，看到的不是源站响应（加随机参数破缓存） |
| 一次发太多变体 | 会触发风控；一个路径一次发一组，间隔 ≥1s |

## 九、边界

- **只读验证**：绕过成功后只读 1 条数据证明可达，**不执行写操作**
- 不爆破：这是"变体尝试"不是字典爆破，单路径变体数 ≤20
- 造成 5xx 或站点异常立即停止
