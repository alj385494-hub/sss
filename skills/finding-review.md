# 独立复核 Validator

> **存在理由**：2026-11-15，我（主会话）判"有危害"的 7 份报告，经独立验证后 **6 份撤稿 + 1 份未决，0 份可交**。
> 不是我技术差，是**自己查自己的证据**这件事本身不可靠：我先有了"这是个洞"的判断，再去找支持它的理由。
> 这个技能把复核交给一个**不知道我的结论**的新 agent。

## 一、为什么不能让挖的人自己判

| 偏差 | 表现（真实发生） |
|---|---|
| **确认偏差** | 只找支持"有洞"的证据，把"令牌不被接受"读成"接受任意令牌" |
| **锚定** | 先定了"中危"，再去凑危害描述 |
| **定义漂移** | "能访问接口"逐步被说成"未授权访问"，最后当成漏洞 |
| **沉没成本** | 打了 40 个请求，不愿意承认"什么都没拿到" |

**独立复核能治这四个，因为复核者没有沉没成本、没有锚、也不需要给我面子。**

## 二、卷宗（传给复核者的一切）

复核者**只看卷宗，不看我的结论**。卷宗只写**事实**：

- 目标（URL / IP:端口 / 系统名）
- 我发了什么请求（完整原文，可重放）
- 收到了什么响应（状态码、字节数、关键字段原文）
- 我做了几次、有没有对照
- **不写**：我觉得是什么漏洞、我定几级、我认为危害多大、下一步能干什么

> 卷宗模板：`runs/tools/review/卷宗模板.md`

**为什么连"我觉得"都不给**：只要复核者看到"疑似未授权读取"，它就会顺着找"未授权"的证据。只给原始报文，它才可能得出相反结论。

## 三、怎么派复核

```
subagent(agent_preset='redteam-worker-vuln-scan' 或 'exploit')
  ├─ 任务里给：卷宗路径 + 本技能 + severity-calibration + §29 三问
  ├─ 明确写：**不要假设这一定是漏洞**，你的任务是判断它成不成立
  ├─ 允许它自己再发 3–5 个请求做独立验证（换方法，不是重复我发过的）
  └─ 要求输出：保 / 撤 / 升级 + 理由 + 缺失的那一环
```

**关键约束写进任务**：
1. 「你的默认立场是**怀疑**，不是确认」
2. 「必须尝试**能否用浏览器正常运行拿到同样的东西**」（§29.2 第一问）
3. 「必须回答：**受害者是谁**」（`severity-calibration` 的 Q1）
4. 「如果答不出，直接写撤稿，不用给我留面子」

## 四、复核者的三个必答问题（判定核心）

```
Q1 别人拿不到的东西是什么？
   —— 具体到字段名/条数/权限动作。答不出 → 撤。

Q2 这是公开的吗？
   —— 同一份内容，用浏览器正常访问能不能拿到？能 → 撤。
   —— 接口行为、版本号、内网主机名、签名算法 → 一律不算。

Q3 它能换来什么？
   —— 令牌/凭据/token → 必须证明能换到会话/数据/操作；换不到 = 物料，撤。
   —— 读到文件 → 必须说清文件里有什么非公开内容。
```

## 五、输出格式（复核者必须照这个写）

```
### 结论
【保】/【撤】/【升级到 X 档】/【未决：缺 Z】

### 一句话
我（复核者）认为这条 成立/不成立，因为……

### 逐项核对
| 项 | 复核结果 | 依据 |
|---|---|---|
| 非公开内容 | 有/无 | 具体字段或"无" |
| 公开可复现 | 是/否 | 浏览器访问结果 |
| 可换取权限 | 能/不能 | 换不到就说换不到 |
| 受害者 | 谁 | 答不出写"无" |

### 独立验证（换方法）
我自己发的请求 + 结果（不复用原卷宗的请求）

### 若撤稿：否定结论
用一句事实级结论写清（"X 与 Y 逐字节相同 → 证明不校验 Z"），不是"我没打通"
```

## 六、复核结论怎么处置

| 复核结论 | 我的动作 |
|---|---|
| **保** | 写报告，定级按复核建议 |
| **升级** | 写报告，但落库前再核对升级依据是哪条实测 |
| **撤** | **直接改 `false-positive`，不申辩**；否定证据链留档 |
| **未决** | 只写进 needs（缺什么），不进报告正文 |

**规矩**：复核说撤就是撤，我不再争论。如果我认为复核判错了，**再派第三个 agent 盲判**，而不是自己推翻。

## 七、常见驳回形态（复核者最该警惕的）

对照 `severity-calibration` 与今天的实战：

| 形态 | 为什么不算 | 今天的实例 |
|---|---|---|
| 读到公开素材 | 浏览器也能拿到 | 附件接口只允许读登录页背景图 |
| 令牌签发但无人接受 | 换不到会话 | `makeJwt` 能签发，10 把密钥全被拒 |
| 只有配置/开关/黑名单 | 无敏感项 | WebConfig 13 项全是业务策略 |
| 只有跳转不返正文 | 没读到内容 | `_redirect` 恒 302/0 字节 |
| 只有 branding | 前端必发 | tenant/info 292B 全是 logo |
| 换出口后参数根本没被读 | 漏洞不存在 | Landray `file=` 与 `a=1` 响应同体 |
| 输入必须先知道受害者标识 | 上限低 | 账号枚举只能"验证已知值" |

## 八、与其它技能的关系

- `severity-calibration`：复核者的**定级尺子**（ATO/PII/RCE 三大母题 + 账号枚举阶梯）
- `api-noauth-hunt` / `web-idor`：被复核对象的**常见误判来源**，复核时重点看
- `butian-rejection-cases`：如果复核结论是"补天会驳"，按它给的理由写撤稿说明
- `field-pitfalls`：核对"参数是否真被读取""同体≠放行"这类技术判定
