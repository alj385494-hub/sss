## 靶标台账（本机环境专用）

> **每次测试结束都要更新**——不管有没有成果、有没有报告。台账是用户判断「哪些靶标还没测」的唯一依据，
> 漏更新会导致下次重复测同一个靶标，或者永远不知道测过。

### 台账位置与格式

| 项 | 值 |
|---|---|
| 文件 | `<HOME>\Desktop\域名信息汇总表.xlsx` |
| 工作表 | `Sheet1` |
| 表头 | `单位名称` / `域名` / `IP 段` / `排除项` / `状态` |
| 状态格式 | `已测(YYYY-MM-DD)`　例：`已测(2026-11-11)` |
| 未测的写法 | `未测`（或空） |

### 怎么做（用现成脚本，别手改）

```bash
PY="<HOME>/.dsh/dsh-runtimes/dsh-primary-runtime/dependencies/python/python.exe"
S="runs/tools/update_status.py"

"$PY" "$S" --list                                  # 先看现状
"$PY" "$S" "<靶标单位全称>" --dry-run               # 演练，确认命中的是哪一行
"$PY" "$S" "<靶标单位全称>"                         # 正式写入（自动备份 + 复核）
```

脚本行为：
- 按「单位名称」**模糊包含匹配**，只改命中那一行；命中多行会列候选并退出
- 写前备份到 `runs/backup/域名信息汇总表-<时间戳>.xlsx`
- 写后重新读取复核，值不一致会报错

### 硬规矩

1. **只改自己测的那一行**，绝不批量改其他行（其他靶标可能是用户手动维护的状态）。
2. **表格里没有这个靶标时，不要自己插行** —— 先问用户要不要新增（行顺序/格式是用户维护的）。
3. **日期用实际测试完成当天**，不是开始那天。
4. **有成果和没成果都要更新**：0 条可提交漏洞也是「已测」，否则下次会重复劳动。
5. 状态只写 `已测(日期)`，不要在后面追加「有 3 个漏洞」之类——报告在 `runs/<靶标>/reports/` 里有。

### 收口清单里加一行

```
- [ ] 桌面《域名信息汇总表》里本靶标状态已改为 已测(YYYY-MM-DD)，且复核一致
```

### 台账被占用怎么办（实测坑）

Excel 被 WPS / Office 打开时，`openpyxl` 保存会抛 `PermissionError: [Errno 13]`，
`os.replace()` 抛 `WinError 32`，桌面上会多出一个 `~$域名信息汇总表.xlsx` 锁文件。

| 做法 | 说明 |
|---|---|
| ✅ **先探测** | `open(path,'r+b')` 试写；或看桌面有没有 `~$` 开头的锁文件；或 `ps -W \| grep -iE "et.exe\|EXCEL.EXE"` |
| ✅ **被占用就停下记录** | 把「命中行 / 原状态 / 目标状态 / 失败原因 / 锁文件 / 恢复命令」写进 `pipeline-state.md` 单独一节，并在最终总结里明确告诉用户 |
| ✅ **给恢复命令** | `python runs/tools/update_status.py "<单位全称>"`（脚本自带备份+复核），用户关掉 WPS 后一条命令即可 |
| ❌ **绝不强杀进程** | 杀 `et.exe`/`EXCEL.EXE` 会丢失用户未保存的编辑，属破坏性操作。**必须让用户自己关** |
| ❌ 不要用 COM 硬写 | WPS 每个文档独立进程，`Ket.Application` 新建实例 `Workbooks.Count=0`，拿不到已打开的文档 |

> 实测（2026-11-12，jiaoyu.cn）：执行侧完整试了 `open(r+b)`、`os.replace()`、COM 三条路，全部失败后
> 正确选择"记录 + 给恢复命令 + 不强杀"，这是**正确处置**，不是失败。
