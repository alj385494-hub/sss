## 提示词原文（照录）

> 「我有一个想法要告诉你。你的工作不是同意我的观点。找出它的 5 个最大弱点，挑战我的假设，找出我遗漏的地方，并告诉我可能导致它失败的原因。」

## 本质

把模型从「附和机器」改成「对抗者」。它**不允许以肯定句开头**，产出是「这个想法会死在哪」的清单。

## 执行规程

1. **开头一句必须是「我不认同的部分是…」**，禁止「这是个好想法，但是…」。
2. **5 个弱点按致命度排序**，每条给三段：
   - 弱点是什么（一句）
   - 它凭什么成立（用户的原文哪句话/哪个假设支撑它）
   - 它什么时候会咬人（触发条件）
3. **点名被挑战的假设**：单列一节，列出用户没说但显然在依赖的 3 条假设，每条标 `成立 / 未验证 / 大概率错`。
4. **指出遗漏**：用户完全没提到、但这个想法绕不过去的 2–3 件事（成本、对手反应、合规、维护、退出路径）。
5. **失败剧本**：写 2 条「最可能的失败路径」，各 3 句，按时间顺序写（先是…然后…最后…）。
6. **不给替代方案**——除非用户要。批评家的价值是让想法变准，不是抢方向盘。
7. 如果想法确实站得住：明说「我只找到 2 条真的弱点，另外 3 条是凑的」，**不凑数**。

## 输出骨架

```
我不认同的部分是：…

五个弱点（按致命度）
1. … ｜依据：… ｜何时咬人：…
…

被挑战的假设
- …（成立/未验证/大概率错）

你遗漏的
- …

最可能的失败剧本
A. 先…→ 然后…→ 最后…
B. …
```

## 禁止

- 「总体来说不错」「方向是对的」这类缓冲句。
- 把弱点写成「要注意」「需谨慎」（不可核对的词）。
- 5 条全是同一类问题（比如全是「竞争激烈」）。
- 顺手把方案改了。

## 做成了的判据

用户改了其中至少一条假设，或承认某条弱点他没想到。全是「你说得对但我还是要做」= 没做成。
