# 未授权 API 猎取

> 目标不是"扫到接口"，而是**证明某个接口在没有合法凭据时能读出业务数据**。
> 扫到但读不出东西 = 没有漏洞。

## 一、什么时候用

| 迹象 | 说明 |
|---|---|
| 页面是 SPA / 小程序 / APP 后端 | 接口在前端可见，鉴权常在客户端"假装"做 |
| 存在 `/swagger`、`/v2/api-docs`、`/openapi.json`、`/graphql` | 接口清单直接可读 |
| JS 里出现 `api/`、`baseURL`、`/v1/`、`/apix/` | 隐藏接口的来源 |
| 某个接口在浏览器里返回 200，但换工具/换账号返回 401 | 鉴权实现不统一 |

## 二、前置

- 一个能保留原始路径的 HTTP 客户端：`curl --path-as-is` 或 Burp Repeater
- 至少一条**已知需要鉴权**的接口作为对照基线
- 噪声纪律：单接口探测 ≤5 req/s，不做字典式全量遍历

## 三、执行

### 阶段 1 · 发现接口清单

| 手段 | 动作 | 判据 |
|---|---|---|
| 前端 JS | F12 全局搜索**碎片关键词**（`api/`、`user`、`order`、`v1`），不搜完整路径 | 搜出页面未出现过的路径 |
| 文档路径 | 逐个试 `/swagger-ui.html`、`/swagger-resources`、`/v2/api-docs`、`/openapi.json`、`/api-docs` | 返回 JSON 接口清单 |
| GraphQL | 试 `runs/tools/paths_graphql.txt` 里的路径；命中后发内省 `{"query":"{__schema{types{name}}}"}` | 返回 schema |
| 版本枚举 | 把已确认的 `/v1/xxx` 换成 `/v2/`、`/v3/`、`/internal/`、`/admin/` | 新版本返回 200 |
| 报错反推 | 故意传错参数，看错误信息里是否吐内部路径 | 错误信息含接口名/路径 |

### 阶段 2 第 0 步 · 先拿"拒绝基线"（能省一半预算）

先测**不存在的方法**与**裸前缀**（如 `/api/v2/index.php/zz/qq`、`/api`），记录状态码+长度+body。
- 若不存在的路径与真实接口返回**同一个响应体**（同码+同长+同 body）→ 鉴权挂在**路由分发之前**
  （网关/中间件级），此时 D1–D5 逐接口枚举**全部无意义**：立即停枚举，转"能不能拿到 token / 能不能绕网关"。
- 实测（2026-11-14 某网络设备厂商 Whistle 开放平台）：16 个文档接口 + 裸前缀全部同一个 51B 401
  → "文档里哪个接口忘加 access_token"这条路从架构上不存在。
> 依据：本判据是我们 2026-11-14 实测归纳（非引用）。架构前提有社区文章佐证：
> 奇安信攻防社区《浅析JAVA代码审计中的"幽灵代码"》指出鉴权常发生在 Filter/Interceptor/AOP 层、控制器之前
> （https://forum.butian.net/share/1118 ，2021-11-19）。


### 阶段 2 · 分档探测鉴权（**关键步骤，别只试一次**）

对每条候选接口，依次试下面 5 档，**记录每档的状态码与响应长度**：

| 档 | 做法 | 命中含义 |
|---|---|---|
| **D1 无凭据** | 不带任何 Cookie/Token | 最严重：完全裸奔 |
| **D2 空凭据** | `Authorization: Bearer`（空值）、`token: `、`Cookie: session=` | 鉴权只判"存在性" |
| **D3 无效凭据** | 随便一个 JWT/随机串 | 签名未校验 |
| **D4 过期/旧凭据** | 之前抓到的旧 token | 会话未失效 |
| **D5 换方法** | 同一路径换 GET/POST/PUT/DELETE/PATCH | 鉴权只挂在部分方法上 |

> **D5 常被忽略**：很多系统只在 GET 上加了拦截器，PUT/DELETE 直接放行。

### 阶段 3 · 判定是否真泄露

拿到 200 **不等于**泄露。逐条核对：

| 检查 | 通过标准 |
|---|---|
| 响应体是业务数据吗 | 有业务字段（id/name/phone/orderNo…），不是 `{"code":401}` 也不是 SPA 的 `index.html` |
| 有没有 SPA 回落页 | 长度与首页一致 + 内容是同一份 HTML → 是回落，不是接口 |
| 数据是不是公开的 | 商品列表/公告这类公开数据不算 |
| 能否量化规模 | 用 `pageSize`/`total`/`count` 让服务端**自己报总数** |

### 阶段 4 · 有界读取（红线）

- 只取 **1–3 条样本**证明字段，**不批量翻页、不导出**
- 用接口自报的 `total` 说明规模，不靠实际拉取
- 敏感字段在报告里脱敏（手机号 `138****1930`）

## 四、证据要求

1. 请求原始报文（含完整路径与方法）
2. 响应片段（前 300–800 字节，含字段名与 1 条脱敏样本）
3. **对照组**：同接口带合法凭据的响应（证明"本来需要鉴权"）
4. 若走 D5 换方法命中，附两个方法的响应对比

## 五、失败判据（什么时候放弃这条线）

| 现象 | 判断 |
|---|---|
| 全部 5 档都 401/403，且无绕过可能 | 该接口鉴权正常，放弃 |
| 200 但响应是 SPA 回落页 | 不是接口，放弃 |
| 200 但字段全是公开信息 | 不构成泄露 |
| 需要签名（ts+nonce+mac）且算法未泄露 | 转「签名逆向」路线，不要硬试 |

## 六、常见坑

- **只试无凭据一次就下结论**：漏掉 D2–D5 四档，命中率会低一半以上
- **忽略网关与源站的差异**：CDN 返回 403 不代表源站也 403（见 `bypass-401-403`）
- **把登录页当接口**：登录接口返回 200 是正常的，判据要看是否返回**业务数据**
- **扫太猛**：一次性对 500 条接口发请求会触发风控，也会打挂小站
- **"长度相同"不等于"内容相同"**：实测 `Login_weixinLogin.action` 的 `success` 与 `failure` **都只有 7 字节**，
  只比 Content-Length 会把认证失败当成功。**短响应一律 `od -c` / `xxd` 看字节**（2026-11-14 华东交大）。

## 七、边界

- 只读：不 POST/PUT/DELETE 创建或修改数据
- 不导出、不缓存敏感数据到本地
- 发现能改数据的方法（如 DELETE 可用）时，**只记录方法可用性，不执行成功**

## 八、识别"框架标准拒绝"，别把它当卡点（2026-11 实测）

某些框架的 401 是**设计如此**，不是你没找对方法：

| 框架 | 标准拒绝特征 | 结论 |
|---|---|---|
| **ABP (ASP.NET Boilerplate)** | 401 + `当前用户没有登录到系统！`（`AbpAuthorizationException`） | `[AbpAuthorize]` 默认即拒，**这是正确行为** |
| Spring Security | 401 + `WWW-Authenticate: Basic` | 正常 |
| RuoYi | 401 + `{"code":401,"msg":"认证失败"}` | 正常 |
| ThinkPHP 自研 | 自定义 JSON `{"code":0,"message":"失败"}` | 需再试参数，不一定是框架 |

**另外**：ABP 的 `AbpServiceProxies/GetAll` 是**按设计公开**的接口清单（它不是漏洞，
但可当作权威接口清单来源用）。

> **判据**：当 401 的文案与某框架的默认拒绝文案**逐字一致**，且该框架文档写明"默认拒绝"，
> 就应判定为**鉴权正常**并收工，而不是反复换 payload 耗预算。

> **补一条实测（2026-11，某论坛类站点）**：接口前缀常常**多版本并存**，
> 只按 `grep "/wap_api/"` 找会漏掉大部分面。本案 172 条接口的实际分布是
> `/v5_0/*` 122 条、`/v4_0/*` 32 条、`/wap_api/*` 18 条 —— **单看 `/wap_api` 会漏 87%**。
> 做法：在前端 api 模块里同时 grep `"/v[0-9]_[0-9]/"`、`"/api/"`、`"/wap_api/"` 三类前缀，
> 然后**同一功能在 v4/v5 里都试一遍**（老版本不一定更弱，但字段常不同，可能多吐一个手机号）。

## ⚠️ 判定门槛：未授权 ≠ 有危害（2026-11-15 实战教训）

命中"无凭据返回 200 + 数据"之后，**必须再答一个问题**：返回的是不是**公开信息**？

| 返回内容 | 定性 | 处置 |
|---|---|---|
| 网站 logo / 登录页背景 / 二维码 / 公开公告 / 帮助文档 / 已脱敏数据 | **公开素材，无危害** | **不交**（审核会问"泄露了什么非公开内容"） |
| 业务数据：公文、名单、通讯录、订单、患者/学生信息、内部主机与配置 | 有危害 | 按泄露内容与边界定级 |
| 内网 IP / 内网主机名（无业务数据） | 平台**忽略项**（"无法直接利用的数据"） | 不单独交，只作危害加剧证据 |

**判定方法**：先摸清服务的**权限边界维度**（`modcode` / `moduleId` / `type` / 命名空间 / 租户 ID），
再问"匿名侧被允许的那一块里，有没有非公开内容"。**不要因为"能返回数据"就当漏洞。**

**反例（2026-11-15 河北医大 iOffice10 `/api/Attachment/File/GetList`）**：
零 Cookie 返回 `200` + 附件元数据，还能匿名下载文件本体 —— 看着像标准未授权。
实测服务端按 `modcode` 收口：匿名只允许 `Setting$WebSite_*`（网站 logo/背景/二维码），
业务命名空间（`Notice$Notice`/`Doc$Doc`/`Flow$FlowTask`/`Address$AddressBook`）一律 `Status 5000` 拒绝；
把 objectid 换成**合法值**也照样 5000（被拒的是 modcode，不是 objectid）；
`limit=1000`/`page=2` 仍只返回 1 条且逐字节相同（无隐藏分页）；`id/ids/directoryid` 全 5000（无按 ID 旁路）。
唯一命中的样本是**登录页背景图**，登录页本就对所有人展示 → **撤稿**。

**配套检查（每个"未授权"命中都要做）**
1. **换命名空间**：不只用命中的那个键，试同前缀/同层级的其它键，看拒绝边界在哪；
2. **给合法值**：objectid/id 传有效值，确认拒绝来自**权限维度**而不是参数错；
3. **看分页是否被忽略**：`page=2` 与 `page=1` 逐字节比对——相同说明返回全集，"只有 1 条"是真的只有 1 条；
4. **找旁路**：`id`/`ids`/`directoryid`/`fileId` 等其它入口，确认没有第二条路；
5. **问一句"我拿到了什么别人拿不到的东西"**——答不上来就是无危害。
