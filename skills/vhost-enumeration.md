# 虚拟主机枚举

> 一个 IP 上挂 30 个站是常态（尤其是高校/事业单位的反代）。
> **只按域名列表测，会漏掉没在 DNS 里出现的站点。**

## 一、先判断"是否共享主机"

```bash
# 1. 多少子域指向同一 IP
awk '{print $2}' resolved.txt | sort | uniq -c | sort -rn | head -10

# 2. 直连 IP 默认返回什么
curl -s -k "https://<IP>/" -o /tmp/d.html -w "%{http_code} %{size_download}\n"
grep -o '<title>[^<]*' /tmp/d.html
```

如果直连 IP 返回的**不是** DNS 里任一子域的内容 → 说明还有别的 vhost。

## 二、五个发现途径

### 1. 证书 SAN（最快）

```bash
echo | openssl s_client -connect <IP>:443 -servername <任一域> 2>/dev/null \
  | openssl x509 -noout -text | grep -A2 "Subject Alternative Name"
```
**多域名证书常把同 IP 的所有 vhost 列出来。**

### 2. 反查（PTR / 同 IP 域名）

```bash
dig -x <IP> +short
# 或用被动 DNS 服务查该 IP 的历史域名（免费额度有限）
```

### 3. Host 头爆破（用字典）

```bash
while read h; do
  code=$(curl -s -o /dev/null -w "%{http_code}" -K <(printf "url = \"https://%s/\"\nheader = \"Host: %s\"\n"$IP $h) -k 2>/dev/null)
  echo "$code $h"
done < hosts.txt | sort -u
```
**字典来源**：已收集的子域名 + 常见前缀（`admin` `oa` `jw` `lib` `vpn` `mail` `api` `test`）+ 单位机构名。

### 4. 泛解析检测（先做，否则全是假命中）

```bash
curl -s -o /dev/null -w "%{http_code} %{size_download}\n" "https://<IP>/" -H "Host: random-nonexistent-abc123.example.com"
```
若返回 200（默认站），说明**泛解析**：需要按响应长度差异判断真实命中。

### 5. 从默认站里的链接反推

默认站（尤其是反向代理的错误页、目录列表）常列出配置的站点名。

## 三、判定标准

| 结果 | 结论 |
|---|---|
| 不同 Host 返回**不同标题/内容长度** | ✅ 不同 vhost |
| 所有 Host 返回同一页 | ⚠️ 单站点（或泛解析） |
| Host 对应站点返回 403 | ⚠️ 存在但受限 |

**关键**：用**响应长度 + 标题**做区分，不要只看状态码。

> **动手前必须先测三样基线，否则几十个域名的"命中"全是假的**（2026-11-14 华东交大 `.228` 实测）：
> 1. **未知 Host 的响应**：实测是 **502 / 2774B**（不是 200 泛回）——它是可用的 oracle，不是"页面不存在"；
> 2. **SPA 站点的 soft-404 是 200**：`ecard` 基线 200 / 1254B，按状态码判会把 227 条路径全当命中，
>    必须用**响应体大小 / 内容差异**区分，状态码对 SPA 无效；
> 3. **同一台反代的 403 与 404 可能同体、同长度、甚至同 title**（深信服实测 403/1363B、404/1359B、
>    title 都是 `Error Page`）→ 判定要落到 body 里的错误码文本（`<span>403</span>` / `error_page__title`）。

## 四、证据要求

1. 共享 IP 的证明（多少域名指向它）
2. 每个 vhost 的请求（Host 头）+ 响应标题/长度
3. 泛解析基线（随机 Host 的响应）

## 五、失败判据

- 随机 Host 与所有候选返回完全一致 → 泛解析且无区分，放弃
- 只有 1 个域名指向该 IP → 无需 vhost 枚举

## 六、边界

- Host 头字典**≤200 条/IP**，间隔 ≥0.5s
- 只做 HEAD/GET，不探测管理路径（那是后续阶段）
- 不做整 C 段扫描

## 七、常见坑

| 坑 | 说明 |
|---|---|
| 不做泛解析基线 | 会把默认站当成所有 Host 都命中 |
| 只看状态码 | 200/200/200 但内容不同才是重点 |
| 忘记 HTTP 和 HTTPS 都试 | 有些 vhost 只在 80 上 |
| 字典里没有单位独特名 | 加机构名缩写/拼音/英文 |

## 实战教训（2026-11，某高校 <IP>）

这轮真跑出来 5 条，已有判断可直接套用：

### 1. 默认站的响应**可能是 502，不是 200**

本目标的默认站是 **502 / 2768B**（md5 固定）。若不先实测基线，会把 **112 个 502 全误判成"站点存在"**。

> **规则**：基线必须实测，不要假定默认站是 200。记录默认响应的 `状态码 + 长度 + md5`，
> 后面所有命中都与它比对；**与基线 md5 相同的一律不算命中**。

### 1.1 同一靶标的多个 IP，基线**可能各不相同**——只有"RST 型"的 IP 值得枚举

2026-11 某高校实测，三个共享反代的基线三种样子：

| IP | 未知 Host 的响应 | 能不能枚举 |
|---|---|---|
| `<IP>` | **`000` / 0B（TCP RST）** | ✅ 最干净的 oracle：只要不是 000 就是真实 vhost |
| `<IP>` | `403` / 239B（通配 vhost） | ❌ 176 个名字全回同一页，零区分度 |
| `<IP>` | `403` / 199B（通配 vhost） | ❌ 同上 |

**教训**：本轮 528 次探测里，**352 次（.206 + .205）全是浪费**，最后只在 `.221` 上挖到 1 个真新子域（`app.csu.edu.cn`，有真实 A 记录却不在 920 子域候选里）。

> **规则**：
> 1. 先对**每个 IP** 用 2–3 个随机名字测基线，**再**决定要不要对它投入字典。
> 2. 基线是**通配 200/403/502** 的 IP → 直接跳过，别做 Host 枚举（除非改用证书 SAN / 被动 DNS）。
> 3. 基线是 **RST(000)** 的 IP → 优先打，这是信息量最大的信号。
> 4. 命中后**必须回 DNS 确认真假**：`getent hosts <名字>`。有 A 记录且不在原候选列表 = 真新发现；
>    无 A 记录却通 = 可能是 IPv6-only（先查 AAAA，见教训 5）。

### 2. 字典别用已知子域回填（**最大的坑**）

本轮字典 = 176 个已知子域 + 24 个环境名（触 200 上限）→ 命中 57 个 200，
但**与 DNS 比对后新发现 = 0**。原因很简单：**用已知名字去验证已知资产，等于自我验证**。

> **正确做法**：字典应以**"DNS 里没有的名字"**为主——单位简称/拼音/英文缩写/
> 部门代号/项目名/历史系统名；已知子域只用于校准基线，不占字典配额。

### 3. 通配符证书对 vhost 发现零帮助

证书若是 `*.domain.com`，SAN 里不会有其他名字 → 不要在这条路上花时间。

### 4. 「vhost 集合 == DNS 集合」是有价值的负面结论

本轮证明该 IP 的所有 vhost 都能在 DNS 里找到 → **以后不必再用 Host 头挖这个 IP**。
把它写进 state 的"放弃项"，比留一句"未发现"更省下一轮预算。

### 5. "DNS 没有但有 vhost"要区分 IPv6

本轮 4 个"无 A 记录却有 IPv4 vhost"的，全是 **IPv6-only 站点**（AAAA 有记录），
不是新站。遇到这种情况先查 AAAA 再下结论。

### 6. 80 端口常给 302

57 个 200 的站点，80 端口全部返回 **302 / 137B**（跳 HTTPS）。
所以**判命中只看 443，80 只用作补充信息**，别把 302 当差异。

### 7. 基线值**不可预设**（403 / 502 / 200 都见过）

已知案例的默认站基线分别是：**502**（某高校）、**403**（某医院）、200（常见）。
预设"基线是 200"会让你在内网 ACL 场景下做出完全错误的判断。

**实测（某医院）**：源站基线 403，12 个端口 × 5 个 Host **全部 403**，
响应长度只随事件编号抖动（同一模板页）→ **Host 头根本不参与判定** →
该 IP 的 vhost 枚举**直接判"不可做"**，写进放弃项，别再花预算。

> 判据：若"未知 Host"与"已知 Host"的响应状态码+长度**无稳定差异**，
> 说明网关在 Host 之前就拦了 → 不可做 vhost 枚举。
