# 执行角色教训库（按角色）

> 定位：**快变层**，由主会话每轮结项时更新；**稳定层是技能正文**——同一条教训出现 2 次以上，
> 必须写进对应技能（`nuclei-scan`、`web-idor`…），不能只留在这里。
> 用法：派活时写「**开工先读本文件你那一节**」（或把该节直接贴进任务描述，双保险）。
> 为什么不做成 skill：2026-11-14 用户拒绝新增 `~/.dsh/skills` 文件，走工作区文档 + 派活强制阅读。

## recon（信息收集）

1. **必须回写测试状态**：测完立刻 `redteam_asset_test`（status/test/surface）。
   反例：2026-11-14 华东交大，库里有 16 个资产但 `test_status` 全 `untested` → 下一轮必然重复打。
2. **泛解析陷阱**：任何域名先测通配符再解析；解析到泛解析 IP（如 `haust.edu.cn` → <TARGET_IP_3>）的一律丢弃或标"疑似泛解析"。
3. **UA 隐身**：目录发现必须跑两轮 UA（curl 默认 + 浏览器 UA）。实测 lldong.com:8888 宝塔面板对默认 UA 恒返回 404/146B，换 UA 后 200/30587B。
4. **DNS 投毒**：本机解析可能是 `240e:45::8888` 黑洞 → DoH 取 IP + `curl -k --resolve`，**禁止改系统 DNS/hosts/代理**。
5. **只收集不验证**：疑似漏洞点只记线索（写进 `test`/`surface`），交给 vuln-scan，别自己判漏洞。
6. **归属证据**：每个得分资产至少一种（ICP / 证书 CN / 页脚版权 / 单位落款）+ 首页截图，`redteam_shot_add` 登记。
7. **端口与目录要限速**：不做全 65535、字典 ≤300 条；敏感路径逐条（≥1s）。
8. **SPA 的 soft-404 是 200，不是 404**：判据必须用**响应体大小/内容差异**做基线，状态码对 SPA 完全无效
   （实测华东交大 `ecard` 基线 200/1254B，按状态码判会把 227 条路径全当命中）。
   反面：`.228` 未知 Host 基线是 **502/2774B**，也不能当 200 用。→ 先测基线，再决定判定维度。
9. **跨出口做可达性比对，必须同批跑 2–3 个已知可达目标作正对照**，且比对 `http_code + size` 而不只是连通性。
   否则两种误判都会发生：把"我这台出口整片被 ACL 挡"误报成"目标全死"，或把"探针写错"误报成"不可达"。
   （2026-11-14 河南科大：11 台 × 80/443 全 fail，靠 `www`/`vpn`/`idp`/`lib2` 四个正对照才敢下结论）
10. **"blocked" 与 "dead" 是两个结论**：ICMP 通 + TCP 全堵 = 源 IP ACL（记 blocked，附出口 IP 与日期）；
    ICMP 也不通且多出口都不通才可能是 dead。写错会让我白找出口或白放弃。

## assess（资产梳理）

1. 逐条评估并**全部落库**（`redteam_batch kind=assess`）；只在脑子里排序 = 没做。
2. 排序口径：**P0 能进内网的 RCE > P1 ≥1 万条三要素数据 > P2 其它**，不按"最容易扫的 Web"排。
3. 非 Web 资产（AD/VPN/云/K8s/网络设备/文件备份/AI/Agent）单独标注，按 `specialist-paths` 分流给对应打法。

## vuln-scan（漏洞发现）

1. **一次只做一个资产**；五项（surface/web/auth/cve/app）完成才 `redteam_asset op=close`。
2. 批量 nuclei/ffuf 只当**候选**，不能代替深挖；命中要复核出证据。
3. 有 WAF 的站点 **404/200 基线不可信**：去无 WAF 兄弟主机或换 Host 做基线（某中医院 oa、河南科大属此类）。
4. 盲打无回显 → `oob-verify` 带外确认，别把"200 了"当"打穿了"。
5. 每条漏洞落库必须带**完整原始 request**，否则只能停在 `candidate`。
6. 401/403 先想 `bypass-401-403`，不要急着报"未授权访问"。
7. **统一错误页产品（Sangfor / Apereo 这类）的 403 与 404 可能同体同长度，连 title 都一样**
   （实测华东交大 EasyConnect：403/1363B、404/1359B、title 均为 `Error Page`，只差 4 字节）→
   基线必须「状态码 + 长度 + title + **body 里的错误码文本**」四重对齐；只比长度或只看状态码都会误判。
   河南科大 aTrust 的 403/404 则同为 192B —— 同一厂商不同产品基线还不一样，**必须现测**。
8. **遇 403 先加载 `bypass-401-403` 再试变体**：今天有 agent 凭记忆只试 5 种就准备定论，加载正文后按 12 类补齐。
   结论"碰巧对"不等于流程对。
9. **注入类要先证明"注入点存在"再打 payload**：S2-045 的判据是"缺 boundary 的 multipart 是否触发解析异常"——
   不触发就说明该解析点不生效，后面回显/时间差/S2-016/S2-032 都不必再发（华东交大 jwxt 实测）。
10. **前端加密不等于漏洞**：硬编码 DES/AES 密钥（如 jwxt 的 DES-ECB）只能证明"密文可重放"，
    要升级须有真实账号密文对照，否则停在 candidate，别写成高危。
11. **先加载技能再动手**：今天有 agent 先按任务描述里的"手法"干活、干完才去补载技能（它自己承认了）。
    任务描述给的是"做什么"，技能正文才是"怎么判定"，顺序反了就会漏判据。
12. **端口猜服务的命中率远低于 vhost 枚举**：实测 .196 六端口里 3000/8080/9090 全是空壳（Grafana/Prometheus/Tomcat
    假设全灭），真正的价值在 312 个子域 DoH 解析里筛出的 13 个 vhost（研究生系统明文直出、缴费系统直出、4 个被零信任拦）。
    → 拿到一台网关**先做 vhost 枚举，再猜端口服务**。
13. **基线长度可能随请求 URI 浮动**（实测长错误页 10.79–10.83KB 随回显 URI 变化）→ 长度只能当"量级"参考，
    判定必须落到响应体里的固定文本/错误码。

## exploit（漏洞利用）

1. P0 先拿**服务器权限**，且马必须是**冰蝎/哥斯拉加密马**并实测能连上（一句话马用户连不上，不算交付入口）。
2. 拿到主机立刻建隧道并**实测能访问内网目标**；`entry_kind` 必须写清目标侧那一端——**自己 VPS 上开的代理不算突破**。
3. 数据面（P1）只取 **1–3 条脱敏样本 + 接口自报条数**，绝不批量拖库；用 `redteam_data_proof` 记字段/条数/可复现查询。
4. 供应链/云侧路径用 `boundary-supply`，写清属于哪种情形 + `scope_confirmed`。
5. 拿权限后补 `redteam_host op=coverage`，别只报"拿到 root"就收工。

## internal-recon（内网信息收集）

1. 先 `redteam_session_check` 确认隧道真的能到内网，再动手；没有隧道就如实回报，不手搓内网探测。
2. `netspy-recon` 摸段 → `gogo-intranet` 铺面 → `fscan-intranet` 只做发现（不爆破、不验证漏洞）。
3. 输出**网段/资产/可达性/卡点**给 `internal`，只落库不利用、不记分。

## internal（内网渗透）

1. 先读 internal-recon 的地图，**不重复全量扫描**。
2. 有凭据先做凭据复用与横向提权（账号类必须带 `access_id`）；无凭据立刻转 P2，不原地爆破。
3. 每发现新网段交回 `internal-recon`；长期控制按 `c2-infra`，别到处撒马。
4. 内网机器也要 `redteam_host` 收口，避免"拿了一堆 shell 却不知道哪台能继续跳"。

## 通用（所有角色）

1. **噪声**：≤5 req/s、线程 ≤2；敏感路径逐条发（间隔 ≥1s）。实测 1 秒 10 条会换整站封 IP。
2. **Kali**：同时最多 2 个任务；脚本首行 `exec </dev/null`；后台 `nohup ... >/dev/null 2>&1 &` + disown；单次输入 <4KB（长脚本先写文件再 copyto）。
3. **写库**：显式 `engagement="<单位名>"`；回报给 `asset_id`/`vuln_id`；"回报≠落库"，主会话会用 `runs/tools/dbcheck.py` 对账。
4. **回报固定七段**：结论 / 证据与 id / 数字 / 卡点 needs / 偏离说明 / 自测或复核 / **技能使用情况**。
5. **测试数据纪律**：不向目标业务写红队标识/假身份/XSS 弹窗；只读取证优先；必须写时先问主会话并登记清理。
6. **范围**：T0/T1 可打；T2（旁站/同段/供应商）必须先回报主会话确认；T3 不碰。
7. **优先级**：授权与红线 > 主会话任务描述 > 角色提示词默认路径。

## 2026-11-14 晚 · 新增（华东交大 ecard / zxjf 实测）

- **"被封/被阻断"必须换客户端复测**：Windows 自带 curl（schannel）对含 `../` 的 URL 会**本地 RST**（`Recv failure: Connection was reset`），
  不等于目标 WAF 拦截。实测同一请求换 Kali curl 重放 → 正常 200/0 字节，真实原因是后端扩展名白名单拒绝 + 异常被吞。
  → 判定"WAF 阻断"前，必须换客户端/换工具复测一次；`nuclei waf-detect` 只能证明前面有 nginx。
- **鉴权失败被包装成 HTTP 200 的服务，必须读 body**：RuoYi 系返回 200 + `{"code":401}`（或被 SM4 密文包一层 `{"data":"<密文>"}`），
  只看状态码会把几十条接口误报成"未授权可访问"。判据：**解密/展开后看 `success`/`code` 字段**。
- **`curl --data-urlencode` / multipart 提交 `__VIEWSTATE` 会假性 500**：只有手工 `+→%2B`、`/→%2F` 的 urlencoded 原值才 200，
  否则会把"编码问题"误判成"MAC 校验失败"。

## 2026-11-15 凌晨 · 某中医院一附院实测（新增 3 条）

- **基线要带时间戳；同一站点两次采样不一致时，先判"是否维护/切换窗口"再判路径**。
  实测 `<TARGET_IP_5>` 在 00:00 进入维护：oa/bidportal 全变 `200/1619「系统维护中」`、
  `/portal` 从 403 变 200、**8001 直接 connection refused**。沿用非维护期基线会把"维护页 200"读成"路径存在"。
  → 判据：任何"可信 404/403 基线"都要写采样时间；跨时段重复采样不一致时先怀疑维护窗口。
- **WAF 只加响应头不等改写 body**：奇安信云 WAF（`WZWS-RAY`）实测只追加头，不改状态码与 body。
  但**源站可能有 cookie 门**：`www` 首访不带 `Cookie: visited=1` 返回 200/1263B 假象，带上才 404/1034B 真基线。
  → 判据：过 WAF 的站点先"带与不带首访 cookie"各测一次，再决定基线用哪个。
- **filtered ≠ down**：`<TARGET_IP_4>:7077` 两个出口都 filtered，但同主机 443 是 open → 是防火墙/白名单，不是服务死了。
  识别产品靠官网 HTML 的链接 alt（解出「湖南省中医药综合统计网络直报系统」= 省级系统）→ **判为 T3，一个请求都没发**。

## 2026-11-15 凌晨 · 某大学附属医院实测（新增 2 条）

- **`nmap -p- --min-rate 600` 会打爆家用 NAT，制造"目标全死"假象**：实测双 IP 全端口扫直接导致本机所有出网
  （含百度）间歇 000 约 1 分钟，一度把 `<TARGET_IP_1>/.220` 误判成 down。
  → 判据：**同批必须带正对照**（一个已知可达站 + 一个公网大站），对照也 000 就立刻停手杀进程、等 30–60s 再判；
  全端口扫描一律禁止在家用出口上做。
- **SNI 决定 vhost 判定**：反代网关必须 `curl --resolve "<域名>:443:<IP>"` 保留正确 SNI；
  用 `-H "Host: x"` 改 Host 会让 TLS 的 server_name 不匹配 → **全部 000，误判"站点不存在"**。
  实测 `<TARGET_IP_2>:443`：Host 头法全 000，换 `--resolve` 后 `ydybzf.<客户域名>` 立刻 500 现形。

## 2026-11-15 凌晨 · 河北医大二院实测（新增 3 条）

- **`curl -o` 在连接失败（000）时不覆盖旧文件** → 会把上一次的文件当本次结果读（实测把 `.155:443` 的 title 读成 `.149` 的）。
  → 判据：**每次采样前 `rm -f` 目标文件**，或写到带时间戳的新文件名。
- **HTTPS vhost 只用 `-H "Host:"` 不带 SNI 会被 nginx 回默认站**（实测 apex/www 全测成 615B 默认页，换 `--resolve` 才是 101979B 真站）。
  （与"SNI 决定 vhost 判定"同源，第二次出现 → 建议回流 `vhost-enumeration` 正文）
- **从主站首页外链反推非标端口，命中率远高于按端口猜服务**：本轮 8881(iOffice10)、12542(质控门户)、18442(麻醉质控)、
  `.137:6800`(notice 站) 全部来自首页/导航里的链接，而不是端口字典。→ 可作为 `vhost-enumeration` 教训 #12 的同构补充。

## 2026-11-15 凌晨 · 麻醉质控 18442 实测（新增 2 条）

- **换方法（D5）得到的异常响应，必须先跟"同方法打不存在路径"做对照**：本单 GET 真实接口得 `code -1`、GET 不存在路径得 500，
  差点把"handler 没匹配上"写成"GET 绕过鉴权"。→ 判据：任何"异常响应"都要有第三条对照（不存在路径 + 已映射接口）。
  （同源条目已出现 2 次 → 建议回流 `api-noauth-hunt` 正文，待批）
- **"鉴权先于参数绑定"是可以测出来的强负面结论**：空体 POST 写接口也先返回 `code 600`，说明 IDOR/未授权写都只能在有账号后验证。
  → 遇到这种系统，**不要继续拼参数**，直接写 blocked + "缺账号"的 needs。

## 2026-11-15 凌晨 · 图书馆平台 9000 实测（新增 2 条）

## 2026-11-15 · A1 危害段落被用户质疑后修正（通用教训，全角色适用）

**症状**：把"推演"写进了 1.4 危害段落，格式上像已证实事实，用户一句"这些内容是可以实现的吗"就暴露。
具体三条反例（A1 makeJwt）：
1. 「冒充任意读者访问授权电子资源」——实际 6 次回放全 `jwt verify error`，校验口用的是另一把密钥；
2. 「把用户导向任意外部站点」——只凭负载里有 `url` 字样推测，从未见过一次成功跳转；
3. 「污染访问审计/计费」——**纯因果臆测**：伪造令牌不写日志，只有令牌被接受时那次访问才以该 userId 记账。

**判据（今后凡写危害都过这一遍）**：
- **危害必须分三层写**：①**已实测证实**（有状态码/字段/字节数支撑）②**推演**（表格化：推演内容 + 前提 + **当前状态 ✔/❌**）
  ③**不可主张**（因果臆测，直接删）。
- **凡"没见过一次成功响应路径"的影响，一律只能进第二层**，并写清"需要什么前提、当前是否满足"。
- **禁止因果臆测**：不要写"可污染审计/可影响计费/可导致业务损失"这类没有观测到的推演链；
  这类链条只有在**实测到一次成功**后才能上升为事实。
- **"完整暴露/完全掌握"这类绝对词要有逐字段证据**；只看到明文但字段语义未确认时，写"明文可见 + 哪些字段未确认"。
- 自检问句：**"这句话我能不能用一次真实响应复现给别人看？"** 不能 → 进推演表或删掉。
