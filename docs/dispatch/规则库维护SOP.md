# 规则库维护 SOP —— 防止 AGENTS.md 再次膨胀

> 立此存照：2026-11-19，AGENTS.md 从 8 节涨到 34 节、22,606 字符，**每轮注入约 14,000 token**。
> 起因是"每次出事就加一条，从不删"。清理后 **16,740 字符（-26%）**。
> 抖音某博主实测：「加入大量无关规则后，每次提问的 Token 消耗增加了 46%」——我们中招了。

---

## 五条机制

### ① 不设上限，只看趋势（2026-11-19 用户纠正）

**原本我设了 18,000 字符硬上限，用户否掉了：「文件肯定越来越大，你这样无异于封杀上限」。**

对。真实需求不是"永远不超过多少"，而是"**该轻的时候能轻下来**"。
硬上限会逼我删掉有用的规则去腾地方——那是本末倒置。

**现在的做法**：
- 平时不设限，`verify_change.py budget` 只报**趋势**（比上次涨/降多少）、**重复长句**、**失效引用**
- 要减负时叫**后勤**（用户说「后勤减负」→ 加载 `logistics-maintenance` 技能）

### ② 准入判定（防该进技能的挤进 AGENTS）

新增规则前必须回答三句：

1. 这条**每轮都必须生效**吗？（不加的话，我是不是每次挖洞/派活都会犯）
2. 还是只在**特定场景**用（写报告时 / 截图时 / 结项时 / 换靶标时）？
3. 是场景规则 → **进技能，AGENTS 只留一行指针**。

| 类型 | 例子 | 去处 |
|---|---|---|
| **每轮铁律** | §29 危害门槛、§31.1 Kali 铁律、§11 写库带 engagement、§13 数据红线 | **AGENTS** |
| **场景规则** | 报告写法（→`butian-submit`）、截图规范（→`butian-submit`）、社区学习流程（→`retro-and-skill-evolution`）、判据校准（→`severity-calibration`） | **技能** |
| **一次性事故** | 某次串库经过、某次封禁时间线、某个工具的踩坑细节 | `runs/notes/` |

**判定问句**：「如果这条不在 AGENTS 里，我下次会不会犯？」
- 会（每次都可能）→ AGENTS
- 只在特定场景才会 → 技能
- 只是留个记录 → notes

### ③ 合并优先于新增

- 新教训**先找**有没有相关节，**能并进去就不新开**。
- 同一主题超过 2 节 → 立即合并。

**反例（真实）**：旧 §28.1–28.5 五节讲同一件事（报告怎么写危害），其中 **§28.2 明确写着"覆盖 28.1 第 2 层"，但 28.1 一个字没删，完整躺了 4 天**，占 3,498 字符 = 全文 15.5%。

### ④ 定期体检

每次结项跑一次：

```bash
"$PY" runs/tools/verify_change.py budget
```

它报三件事：
- **预算占用**（超 90% 告警）
- **疑似重复长句**（同一句出现 ≥2 次 = 该合并）
- **失效章节引用**（删节后 `§N` 指向空气）

### ⑤ 删节必须同步改引用

删节不是改完就完——**所有 `§N` 引用都要跟着改**。
本轮删 §28 后，§33.2 还引用「三态归零（§28.3）」，指向了不存在的节。
`budget` 会自动检出这类问题，**每次删完必跑**。

## 三条红线（不许破）

1. **§29 / §31.1 / §11 / §13 永远在 AGENTS**：危害门槛、Kali 铁律、写库带 engagement、数据红线。
   这四条是**每次都需要的判断**，挪进技能就等于每次都要先想起来加载——那就晚了。
2. **删内容前先备份**：`cp AGENTS.md runs/backup/AGENTS.md.bak-slim-$(date +%Y%m%d%H%M%S)`。
3. **清理后必须验证**：`budget` 通过 + `grep` 确认关键判据还在（不许只看脚本打印的"省了多少"）。

## 一次真实的翻车（必须记住）

本轮清理时，我写的脚本把结果写进了 `AGENTS.md.bak2` 而不是 `AGENTS.md`，**但我只看了脚本打印的"省 4,205 字符"就报告成功**。

结果系统注入的仍是旧版全文——**我自己犯了正在修的毛病**（改完没验证）。

教训：**写完必须 `grep` 确认文件真的变了**，不能信脚本的"我改了"。
这就是 §34「L1/L3 验证」存在的原因。

## 每次结项的动作清单

```bash
PY="<HOME>/.dsh/dsh-runtimes/dsh-primary-runtime/dependencies/python/python.exe"

# 1) 预算与体检
"$PY" runs/tools/verify_change.py budget

# 2) 关键判据还在吗（不许凭印象）
grep -c "我拿到了什么别人拿不到的东西" AGENTS.md        # §29 核心
grep -c "所有挖掘/扫描/探测操作一律在 Kali 内执行" AGENTS.md  # §31 铁律

# 3) 改了进程内文件的话，确认要不要重启
"$PY" runs/tools/verify_change.py restart
```
